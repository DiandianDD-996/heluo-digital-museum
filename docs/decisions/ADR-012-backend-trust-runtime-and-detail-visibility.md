# ADR-012：后端信任边界、洛笙运行时治理与详情可见性

- 状态：采纳（2026-11-24）
- 范围：后端与部署；补充 [ADR-010](ADR-010-luosheng-v2-museum-agent.md)，保留 [ADR-006](ADR-006-luosheng-structured-evidence-conflict.md) 的证据约束。

## 决策

1. **信任代理的地址，不信任客户端自报的地址。** 默认只信任回环；Compose 额外信任 Nginx 的固定 `/32`。不可信直连忽略转发头；可信链从最靠近应用的地址开始解析。代理必须净化或追加实际对端，不能将客户端提交的地址当作可信跳。重置密码按 IP 和用户名同次判定；未找到账号与节流都不改变受理响应。
2. **洛笙运营状态和暂存仅在进程内有效。** JSON/SSE 共用 IP、会话、请求号和载荷指纹的重放边界，不设跨访客共享回答缓存。文件暂停优先于管理员运行模式；版本变化后不复用旧模式回答。目录缓存独立于回答缓存，在后台目录写入事务提交后失效。运行模式操作记入数据库审计；模式、限额、计数和缓存本身不做跨进程同步。
3. **馆藏数据库是公开内容的读取来源。** V28 为存量库回填新增列；全新演示库由初始化器在 Flyway 之后写入等价默认值。SEO 从公开详情的发布、删除、分类和关联展品可见性边界读取，使用配置的公开 origin。PocketBay 读包内模板；Compose 读取同一 Nginx 正在提供的模板，避免新旧静态资源哈希混用。动态 HTML 不缓存；未知和不可见详情统一 404。
4. **凭证校验与旧完成接口分离。** 用户自己的预约响应附带基于服务器密钥派生的短码；仅管理员可为已确认预约核销。核销落 `checked_in_at` 并审计，旧 `/complete` 保持历史语义，不计作凭证核销。轮换签名密钥时旧凭证会改变，核销前需重新打开预约详情。

## 影响与边界

默认不部署 Mailpit；开发用测试收件箱仅绑定回环，旧实例须按变更流程显式停止。多副本上线前要设计共享限额、运行模式与缓存失效；本轮不引入额外依赖。外部反代、公开域名、真实 SMTP 与现网数据迁移需在获准发布窗口另行复核。
