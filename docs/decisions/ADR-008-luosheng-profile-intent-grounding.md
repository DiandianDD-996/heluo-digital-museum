# ADR-008：洛笙的档案路由、单一意图与句级引用校验

状态：已实施于「靠谱地基」，未启用正式问答。日期：2026-11-21。适用于中文公众端导览。
关联：[ADR-006 结构化事实冲突](ADR-006-luosheng-structured-evidence-conflict.md) · [ADR-007 跨页参观状态](ADR-007-luosheng-visit-context.md) · [执行方案](../plans/2026-11-21-luosheng-optimization-execution.md) · [总方案](../plans/2026-11-21-luosheng-smart-usable-master.md)

## 背景

「靠谱地基」要回答三个问题，代码里各有一处结构性缺陷：

1. **加第二件藏品要改代码。** 图版卡号、事实来源和纠正词硬编码在 `GuideTurnController` 与 `GuideFollowUpRetrieval` 中，新增展品必须修改 Java。
2. **同一句话被多处解析。** 站点问答、找物、时段、返回看点各自实现正则与优先级，前后端可能对同一句给出不同理解。
3. **“证据约束”只约束引用集合。** 生成结果只校验长度和引用是否属于当轮证据，正文是否被证据支持没有代码校验。

## 决定

### 1. 展品路由档案

新增 `museum.guide.profile-path`，指向版本 1 的只读 JSON 档案；运行时按 `(exhibitSlug, locale)` 取图版、事实来源、纠正词与可承接话题的卡号修订映射。

档案**只做路由，不承载面向游客的事实**。事实仍只来自已签核证据卡；档案无法新增、改写或绕过卡片。

启动时逐项校验：路径非空、严格 JSON、`version` 为 1、展品与语言合法、`stop` 唯一且已知、`view` 与 `stop` 对应、修订号为正、话题卡属于图版卡、同一展品与语言不重复。任一失败拒绝启动，不进入半可用状态。请求时档案缺失或因图版卡不可见而无法解析，按展项不可用处理（404），不返回通用回答。

### 2. 单一意图契约

前端只保留一个解析入口 `parseIntent`，返回判别联合，固定优先级：

```text
取消时段 → 时段查询/澄清 → 返回已保存看点 → 当前页面说明
→ 当前展品取证 → 找物 → 站点导航 → 澄清/未知
```

只有 `object-evidence` 允许请求 `/api/v1/guide/turns`。导航、时段、找物和未知输入在本地确定性解决。旧函数（`discoveryIntent`、`slotIntent`、`requestsSavedLookpoint`）保留为薄投影，内部转调 `parseIntent`，供既有调用点过渡。

规则不是开放域分类器；语料之外的问题落入澄清或未知，不猜测。

### 3. 句级引用校验

生成协议升级为 `luosheng-structured-v5`：`sentences[{text,slot,quote}]` + `references`。

确定性校验全部通过才接受：

- `answer`/`boundary` 的 `text` 在 NFKC 与空白归一后，必须是该 slot 证据的**连续完整句段**，保留原句限定语与标点；
- `quote` 至少 6 码点，且是 `text` 的子串；
- `references` 去重、最多 3，且与实际使用的 slot 集合完全相等；
- 逐句与总长度受限；弃答只接受 `{"text":null,"references":[]}`。

任一失败整份草稿作废，对外仍是 `GENERATION_UNAVAILABLE`，内部记 `guide_generation_rejected` 与实例计数，不记录正文、引文或问题。

## 取代与被取代的方案

- **不采用“自由措辞 + quote 子串校验”。** 固定对照中，该方案会放过“真引文配新事实”（3/3 无依据样本通过）。要求整句是原文完整句段后降为 0/3，代价是接受率降到 7/10。
- **不采用模型比较卡片正文。** 沿用 ADR-006 的判断：同义表述与来源层级会造成误判。
- **不把前端意图与后端取证合成一个模块。** 两者域不同：前端决定“去哪”，后端决定“有什么证据”。合并会让一次改动同时波及路由与取证。

## 取舍与后果

**复用的边界必须说清。** 第二件藏品（测试库河图玉璧）复用了既有 `motif` 看点标识，因此本次证明的是：**同一套后端取证内核可服务任意展品，只要该展品需要表达的看点词汇不超出 `ear/feet/motif` 枚举**。需要“中孔、外缘、翼、喙”这类新部位时，仍要修改 stop 枚举与对应视图映射。也就是说：

- 已成立：新增展品只需增加档案与合成/签核卡片，无展品专用运行逻辑；
- 未成立：任意新展品零改动接入；
- 未涉及：新页面、新图版枚举、前端展签模板。

**自然度上限由卡片正文决定。** 事实句必须原文照录，所以证据卡的文字就是游客读到的洛笙原话。想让回答更自然，只能把卡片改写得更口语并重新签核，不能靠提示词补救。这条把“写文案”和“写内容”合并成同一件事。

**接受率是有意的取舍。** 固定语料 7/10 接受、0/3 假阳性。降低接受率换来的是无依据断言为 0；不为了让更多草稿通过而放宽校验。

## 未验证项

- 真实模型格式服从率与真实生成接受率：未测，固定样本只衡量校验器。
- 正式内容签核：六卡仍待签，正式卡包未生成。
- 开启态部署、真机与真人试用：未执行。
- 档案与签核卡片的长期一致性：目前靠每轮按修订号重新核对；需要内容更新流程配合。
- 已处理：`GuideProfile` 内原 stop→view 常量已删除，`view` 字段一并移除（该字段从未被消费）；档案样例已移出 `main/resources`，改放 `docs/plans/luosheng-eval/ding-profile.example.json`，不再被打进后端包。
- 仍遗留：看点词汇本身仍由前端 `GuideStop` 与界面标签固定；新增部位需要前端与文案同步，后端档案已可容纳任意非空 stop。
- 语言资产（INT-1）：别名、相对日期、人数词、站点关键词与建议问题已移入 `frontend/src/assets/guide/lexicon.zh-CN.json`，新增别名不需要改代码；新增看点仍需改 `GuideStop` 枚举与界面标签。`sync-lexicon.mjs --check` 校验词表与证据卡一致。

## 复核条件

出现以下任一情况时重新评审：

1. 第三件藏品需要的看点词汇超出当前枚举；
2. 真实模型接受率低于固定语料，且原因不是卡片写法；
3. 内容签核流程无法稳定产出可直接照录的卡片正文；
4. 需要多语言公开问答。
