# ADR-007 洛笙的跨页参观状态与动作交接

状态为提议，日期为 2026-11-21。适用于中文公众端导览。产品路径、实施批次和验收标准以[一体化向导终版方案](../plans/2026-11-21-luosheng-unified-visitor-guide-final.md)为准，[上一版](../plans/2026-11-21-luosheng-unified-visitor-guide.md)保留为评审历史。

## 背景

全站面板了解路由名、目的地和三站路线进度。展签了解藏品、展项、图版与确认的看点，服务端取证会话掌握可用于接续的话题。游客从首页接受看点推荐时，这三处需要交付同一份参观意图。一次预约查询还需要一个可回到原展品的位置。[全站面板](../../frontend/src/components/LuoshengSiteGuide.vue) · [现有看点交接](../../frontend/src/lib/luoshengPreview.ts) · [现有取证会话](../../backend/src/main/java/com/heluo/museum/guide/GuideRetrievalSession.java)

## 拟采用的做法

Vue 应用外壳持有一个当前标签页内存中的 Pinia store。页内展签与全站按钮可唤起同一输入和回答区域。路由提供位置，页面声明成功载入的公开内容和能执行的操作。后端继续负责公开性、证据、会话归属、使用额度和回复有效性。

| 信息 | 由谁确认 | 生命周期 |
| --- | --- | --- |
| 参观目标、时长、本轮排除项 | 游客的输入或明确选择 | 目标可在公开页面间接续。改口立即更新，排除项默认仅用于本轮 |
| 当前路由、藏品、关联展项及语言 | 新页面成功加载的对象和实际关联 | 路由开始切换就让上一页对象失效。新页面加载完成后才可执行页面相关动作 |
| 已确认的看点与可用图版、视角 | 游客点选、目标页面确认 | 对象或语言变化时失效。同件详情与展厅可显式交接，接收方核对后生效 |
| 最近可引用的话题及依据修订号 | 服务端成功交付的当前轮次 | 缺证、超时、撤回各走原有对应策略。回看和重新接续时重验全部引用 |
| 一条待继续的任务和一个返回位置 | 游客明确提出顺序，或由看点转去公开服务 | 只保留枚举任务、公开标识、日期或部位。返回时重新读取公开资料 |

建议动作记录包含类型、目标参数、发起页的版本和一次性编号。点击后进入待到达状态，目标页报告真实展品或图版已就绪后消费。连续点击只产生一次有效执行，过时的按钮恢复为按当前页重新提问。用户回退和同一路由换 slug 均触发对象核对。详情页现有的一次性路由状态可用于交接标识。游客自由提问和模型答复只在当前交互中短时使用。

导航和时段直接使用站内路由和公开查询。展品答复从已审签的证据链生成，沿用结构化事实冲突判定。模型可提供基于证据的语言表达，前端采用已注册动作，后端验证事实与权限。[事实判定 ADR](ADR-006-luosheng-structured-evidence-conflict.md)

第 1 批拟确定共用输入框的提问契约，以隔离内测构建接现有受控问答适配器。请求携带本轮编号、公开对象、所选看点和上下文版本。服务端确认当前话题，返回答案、当轮依据和可建议的动作。用获准模型从普通首页走到看点，连续提交两次自拟追问。第 2 批把同一状态接到公开时段和 3D 返回路径。第 3 批以同一契约接正式同源 `POST /api/v1/guide/turns`，用已签资料和生产隔离检查验证候选构建。开发测试端点只供隔离环境使用。[现有 API 契约](../05-api-design.md) · [首页联合试用记录](../plans/2026-11-19-luosheng-acceptance.md#unified-guide-trial)

## 取舍与复核

当前工作树按本次委托随附的方案实现候选。Pinia 维护标签页内存中的访次，页面确认公开对象和图版交接。问答服务按匿名会话绑定访次，检查请求编号、上下文版本、公开性及核准指纹。问答和预设读取均默认关闭。测试使用合成签核包和本机模型协议替身，项目方审签与发布验收待完成。

服务端将游客点选的看点、回答确认的单一看点、当轮依据分别保存。“另一只”优先承接已确认的回答话题，多卡回答无法确认单一看点时回退到游客点过的位置；问出处始终取当轮依据。显式点选看点重置回答话题。候选中，单独说“我说的是脚”或“鼎耳”之类的明确纠正可用相应的已审图版卡确认，不必调用模型；缺卡时不借用旧部位作答。话题变化不会替游客执行切图。

进入预约、馆藏索引、文化专题或文创时，外壳只保存已确认且图注就绪的公开看点与视角，不带入旧答复。换到另一件展品、访问非接续路由、专题加载失败或结束当前参观会清除暂存。预约可直接显示返回入口；其他公共页面在游客主动提出返回后才显示。目标页重新检查公开内容、证据和可读图注后，才确认回到原看点。

图版动作、看点返回和已显示的澄清使用有限分类的匿名计数。浏览器只发送一个类别，同时省略 Cookie、来源页、问题正文和访次标识。连续澄清由同一面板在当前上下文比较实际接受的两轮结果，避免运维端关联访次。Spring 实例累加六项计数，发布时由批准环境接入内部汇总。

继续给两个面板分别添加交接字段，初期改动较少，每新增公开页面都要同步两份当前状态，难以判断哪份“这件”或“刚才”有效。共享内存状态需要收拢旧面板的输入和生命周期，能通过页面确认和会话版本核对实际目标。把每次导航都交给远程模型还会增加延迟和按轮费用。公开搜索、日期和路由本身已有确定的数据来源。

首批保留页面原有的公开阅读和业务表单，接续运行在当前标签。刷新后按当前页面重新开始。进入登录、个人中心、后台、外语界面等超出本次范围的页面时清除参观状态。存储受限时仍能手动打开向导。增加第二件深讲藏品时复核是否只需新增看点、资料和映射。需要跨设备历史、长期画像或新的数据表时单独评审。

2026-11-21 WP1 已在后端用隔离库验证第二件展品。按展项与语言索引版本化路由档案，档案只绑定看点、卡片修订、话题和纠正词；事实仍由 ADR-006 的可见证据提供。继续写死鼎卡号会让每件藏品都改代码，改为由模型选择映射则无法确定性拒绝失配。新档案需在开启态启动时验证，缺失或不合法拒绝启动；这不增加游客端的图版枚举或开放范围。

地基阶段，共用输入框只把判定为当前展品取证的输入发给服务端问答。内部 v5 生成只选取已审、保留句内限定的原文；不能仅靠引文存在来允许模型改写正文。该取舍减少措辞自由度，换取可离线复验的边界；不是对任意问题相关性或真实模型可用性的保证。公开接口和交付前的卡片复核不变。

评审时确认共享状态的归属和跨页保留字段。实施后以首页点击直达看点、两件展品间的切换、查时段再返回、迟到回复作废和默认构建隔离进行实页验收。在受控测试中分别关闭生成和整套向导，验证已有公开页面正常浏览。当前决议待项目负责人评审。
