# 数字展项完整首帧加载修复

## 目标

- 修复青铜鼎在加载完成初期先显示低透明度、纹样和金属质感不完整，随后才恢复完整 PBR 外观的问题。
- 在模型解析、着色器编译和纹理上传完成前保留现有加载遮罩，遮罩退出后一次呈现完整、不透明的模型。
- 保留实体/点云双向切换、相机预设、性能分档、加载失败降级和 Three.js 资源释放行为。

## 关联需求

- F-05：3D 展项具备可理解的加载状态，并能稳定加载、旋转和缩放。
- N-03：桌面与移动端的首屏展示稳定，无突兀的半成品画面。
- N-06：加载、减少动态和交互状态遵循现有视觉与无障碍契约。

## 影响范围

- `frontend/src/components/ThreeExhibitViewer.vue`
- `frontend/src/components/ThreeExhibitViewer.spec.ts`
- `frontend/src/assets/main.css`

不修改 GLB、API、路由、权限、数据库、相机参数、点云 shader 或业务数据结构。

## 根因

GLB 几何体在问题截图中已经完整加载。旧实现随后对所有 PBR 材质执行 `850ms` 的 `opacity: 0 -> 1` 渐显，透明阶段会削弱法线纹样、金属反射和深浅层次，使模型看起来像只加载了一部分。浏览器同时还可能在首个可见帧编译 shader 和上传纹理，进一步放大了该视觉跳变。

## 实施步骤

1. 删除首屏实体模型的材质透明渐显，加载完成后的实体材质始终保持完整不透明。
2. GLB 解析和运行时材质准备完成后，在加载遮罩下执行 `renderer.compileAsync(scene, camera)`。
3. 编译完成后主动渲染一次完整首帧，确保纹理和 PBR 状态已提交，再关闭加载遮罩。
4. 加载遮罩以 `180ms` 仅透明度淡出；减少动态模式直接退出，不引入布局动画。
5. 保留实体/点云切换原有的材质透明动画，并补充测试隔离首屏加载与模式切换行为。

## 验收标准

- GPU 编译 Promise 完成前加载遮罩保持可见。
- 遮罩关闭前至少渲染一次完整首帧，实体材质 `opacity` 为 `1`。
- 首次可见的青铜鼎纹样、法线和金属质感一次完整呈现，不再出现截图中的半透明中间态。
- 实体/点云可继续双向切换，加载失败仍显示封面和重试入口。
- `1433x746` 与 `390x844` 页面无横向溢出、卡片重叠或控制台新增错误。

## 风险

- 遮罩可能比旧实现多停留一次 GPU 编译时间，但用户看到的是稳定完整首帧，而不是提前暴露的半成品模型。
- `compileAsync` 失败必须进入现有失败降级，不能让遮罩永久停留。
- 页面在编译期间离开时必须通过初始化版本和 `disposed` 状态阻止异步回写。
