- 设计力度：系统级精修

## 1. 目标

在不改变现有页面构图、功能板块、路由、API、权限、预约/订单状态机、模拟支付和 Three.js 核心交互的前提下，统一全站浅色模式的表面层级、卡片材质、共享控件、交互状态、响应式和无障碍表现。

本轮不把页面全部改成卡片，也不重新设计信息架构。重点解决：

1. 浅色画布、卡片和输入控件明度过近，元素与背景融为一体；
2. 不同页面仍由历史局部颜色和阴影规则驱动，材质语言不一致；
3. 深墨卡片在个人中心、任务页和后台中面积过大，导致浅色主题像深浅拼接；
4. 卡片、搜索、筛选、表单、状态和按钮的 default / hover / focus / active / disabled / loading / error / success 反馈不完整或不统一；
5. 移动端虽无横向溢出，但固定底栏、卡片边界、横向控件和任务操作的层级仍需统一。

## 4. 第一轮审计结论

### P0：浅色表面缺少可辨别的层级

当前 `--color-paper`、`--color-paper-2`、`--color-surface` 明度靠得过近，部分页面再叠加纯白或半透明白，造成“白底 + 白卡 + 白输入”的同层问题。解决方案不是加重所有阴影，而是建立稳定的四级浅色表面，并让边界、邻接关系和阴影方向共同表达层级。

### P0：历史页面 CSS 仍绕过共享主题

`main.css` 中仍存在大量 hex、rgb、white 和页面级渐变/阴影覆盖；共享 Token 已存在，但未完全拥有最终视觉。实施时需把颜色和状态所有权迁移到语义层，页面样式只负责几何和构图。

### P1：深墨表面使用范围过大

浅色主题保留深墨是品牌优势，但必须限定在：

1. 首页路线板；
2. Explore 的文物媒体舞台或文字叠层；
3. 3D 展项信息板和沉浸式场景控件；
4. 极少数具有明确叙事意义的锚点。

个人资料编辑、预约/订单记录、普通表单、后台编辑区和普通统计卡改回浅色分层，避免深浅主题拼接。

### P1：卡片类型没有明确区分

全站需明确四类容器，而不是一个 Card 包办一切：

- `MediaCard`：以文物、展项、商品图为主体，可点击；
- `NarrativeBlock`：长文、地图、策展说明，通常不悬浮；
- `TaskPanel`：预约、登录、资料、订单和后台表单，强调边界与状态；
- `RecordRow`：预约、订单、后台数据记录，以扫描效率为主。

### P1：移动端结构可用但需要视觉收口

当前主要路由无横向溢出。后续不重新发明移动架构，只需要统一：底部导航遮挡余量、横向日期/筛选的滚动提示、表单字段层级、记录卡边界和后台顶部导航对比度。

## 5. 锁定的设计方向：日间月白展厅 2.0

### 物理场景

年轻访客在自然日光充足的现代博物馆中浏览文物；墙面是冷月白与极浅青灰石材，信息板像薄玉釉和纸张，只有真正悬浮或覆盖媒体的功能层使用半透明材质。

### 色彩策略

采用 `Restrained` 策略：中性冷月白与低彩青灰承担 85% 以上面积；河洛墨绿用于正文和主操作；青玉用于选择、焦点和成功；古铜用于编号、细线和极少量高价值操作；朱砂仅用于危险和错误。

禁止通过大面积米黄、奶油色或装饰性暖渐变表达“传统文化”。文化感来自器物、排版、留白、青铜/玉石材质和结构，而不是泛化仿古色。

### 四级浅色表面

| 层级 | 用途 | 视觉行为 |
| --- | --- | --- |
| L0 全局画布 | 页面最底层 | 冷月白，减少发光感，不使用纯白 |
| L1 页面分区 | Hero 下层、侧栏、内容带 | 比 L0 深 2.5–4 个感知明度点，极低彩青灰 |
| L2 内容表面 | 卡片、表单、记录、购物袋 | 与 L1 有稳定边界；上沿微高光、短落地阴影 |
| L3 控件表面 | 输入、筛选、分段、次按钮 | 比所在 L2 略深半级，形成微嵌入“玉石槽” |

相邻层级不得只靠模糊区分。正常模式至少使用背景差 + 1px 边界两项中的两项；可操作浮层可再增加短阴影。

### 深墨使用合同

- 深墨表面是“展品/媒体舞台”，不是普通卡片默认值；
- 深墨之上只使用暖月白正文、低面积古铜和语义青玉；
- 普通浅色表单、记录和后台区域禁止整块转为深墨；
- 深墨板与浅色画布相邻时，使用媒体边缘遮罩和窄边界，不使用彩色光晕。

## 6. 组件级方案

### 6.1 卡片与容器

#### 可点击媒体卡

- `default`：L2 表面、1px 边界、短方向性阴影；图片和文字的边界明确；
- `hover`：最多上移 `2px`，图片缩放 `1.015`，边框向墨绿/古铜轻微增强；
- `pressed`：`scale(.985)` 或下压 `1px`，从当前显示值开始，不出现跳变；
- `focus-visible`：3px 柔和焦点外环，不能被 `overflow` 裁切；
- `disabled/loading`：几何不变，骨架或局部 loading，不整卡空白；
- 静态信息板、统计板和长文区不抬升。

#### 记录卡 / 记录行

- 优先使用分组线、列对齐和浅色行底，而不是每条记录一块悬浮玻璃；
- 日期、状态、主体和操作形成稳定四列；移动端转为两层记录卡；
- 行级 pending 只锁定当前记录，其他记录可继续使用；
- 危险操作使用朱砂文字/边界 + 图标/文案，不仅依靠颜色。

### 6.2 搜索与筛选

- `MuseumSearchField` 保持单层边界；禁止输入框外再套第二个相同白框；
- 输入区为 L3 微嵌入玉石槽，按钮为墨绿实底；
- placeholder 对比度达到 `4.5:1`；
- 清空按钮、提交按钮、loading 和 error 占位保持固定宽度，避免跳动；
- 分类筛选使用一个连续的分段轨道；active 由背景、文字和底部/内边界共同表示；
- 横向可滚动时提供边缘淡化或局部露出，不能只靠用户猜测。

### 6.3 按钮

- Primary：墨绿实底、月白文字；
- Secondary：L3 面 + 稳定边界；
- Ghost：只用于低优先级文本动作，不与主操作争夺；
- Danger：浅朱砂状态面 + 图标/明确动词；
- 高度至少 `44px`，同一上下文内圆角、文字基线、图标尺寸一致；
- pointer-down / active 立即反馈，释放后从当前值回弹至静止，但不使用 overshoot；
- loading 不改变按钮宽度，成功/失败反馈保留明确文本。

### 6.4 输入、复选框与分段控件

- 输入默认不能是纯白洞口；L3 面与 L2 表单板有半级差；
- label 永久可见，不以 placeholder 代替；
- error 同时提供原因和下一步；
- `GlassCheckbox` 为 20–22px 方形玉釉，选中为墨绿实底 + 月白对勾 + 极细古铜上沿；
- 分段控件不使用渐变胶囊，active 只提升一个层级；
- 自动填充、disabled、read-only 和浏览器验证态都纳入主题。

### 6.5 状态、空态、错误与加载

- Loading：内容型区域使用骨架；按钮和单记录使用局部 loading；
- Empty：说明为什么为空并给出当前页面真实入口；
- Error：说明失败对象、保留用户输入、提供重试或返回；
- Success：使用青玉但不整块染绿；
- StatusBadge：状态点 + 文本 + 边界，不能只靠颜色。

## 8. 动效与交互方案

### 基础时序

- hover / focus 色彩与边界：`160–200ms`；
- 卡片抬升与图片缩放：`180–240ms`；
- 面板/Bottom Sheet：`220–320ms`，从当前显示值开始；
- 页面进入：保留现有 `opacity + 8px`，不增加编排式等待；
- 不引入新的大型动效库，优先复用现有 `motion-v` / GSAP 所有权。

### Apple 式物理原则

- 按下即响应，不等 click 结束；
- 用户可操作的动画必须可中断，不锁输入；
- 进入和退出路径对称；
- 只有手势/动量驱动的对象可以有轻微弹性，本轮普通卡片和按钮不使用弹跳；
- `prefers-reduced-motion` 下取消位移和缩放，只保留不超过 `150ms` 的颜色/透明变化。

## 9. 响应式与无障碍合同

- 固定验收宽度：`320 / 375 / 390 / 414 / 768 / 1440`，补充 `1672 / 1920` 桌面检查；
- 禁止 `100vw`，所有 Grid 轨道使用 `minmax(0, 1fr)`；
- 移动端底部导航上方保留安全区和操作余量；
- 后台表格在窄屏转为记录卡，操作不得横向挤压；
- 正文 `>= 4.5:1`，大文字和关键边界 `>= 3:1`；placeholder 同样 `>= 4.5:1`；
- 焦点环不得被裁切；所有 44px 控件具备语义名称；
- `prefers-reduced-transparency`、`prefers-contrast: more` 和 `forced-colors` 使用实色降级；
- 3D 保留封面/文字降级，Canvas 失败不阻断详情与预约。
