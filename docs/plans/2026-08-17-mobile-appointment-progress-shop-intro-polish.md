# 移动端预约进度与商城标题区精修

## 1. 目标

修复 `/appointment` 移动日期轨道停在半张卡片的问题，并将四步预约进度重做为清晰、克制的导览刻度带；同时优化 `/shop` 移动标题与分类区，移除厚重浮卡和横向滚动条。

关联需求：`F-06`、`F-09`、`F-12`、`F-14`、`N-03`、`N-06`。

## 2. 影响范围

- `frontend/src/assets/task-pages.css`
- `frontend/src/assets/public-responsive-polish.css`
- `frontend/src/assets/MobileAppointmentShopPolish.spec.ts`
- `PROJECT_STATUS.md`
- `docs/01-requirements-traceability.md`

不修改预约日期/时段数据、预约提交、购物车、分类筛选逻辑、模拟支付、API、路由、鉴权或业务状态机。

## 3. 实施方案

- 移动日期轨道按可用宽度稳定显示四张完整日期卡，卡片继续保持 108px 触控高度、横向滚动和停靠行为。
- 四步进度改为单一深玉刻度带：移除圆点连线和分散底板，用编号、分隔线、当前步骤底线与轻高光表达状态。
- 商城移动标题区移除浮卡边框、阴影、模糊与点阵，保留标题和品牌眉题的编辑式层级。
- 四个商城分类在移动端固定为四等分单行控件，不出现横向滚动条或半个按钮。

## 4. 验收标准

- 320/390/430px 下日期轨道初始位置均只显示完整卡片，页面无横向溢出。
- 四步文字在中英文下无裁切，当前/已完成/未完成状态清晰，浅深主题一致。
- 商城标题区不再表现为嵌套浮卡；四个分类完整可见，`scrollWidth === clientWidth`。
- 专项/全量测试、类型检查、生产构建、页面映射和 `git diff --check` 通过。

## 5. 风险

- 两个页面均有多层历史 CSS，必须以最终计算样式和真实浏览器矩形验收。
- 浏览器视口模拟不替代实体 iOS/Android、系统强制颜色和真实触控惯性验收。

## 6. 验证结果

- `/appointment` 在 320/390/430px 下初始均显示四张完整日期卡，第五张可见像素为 `0`；卡宽分别约 `63.03/79.33/89.33px`，高度保持 `108px`，页面横向溢出为 `0`。
- 四步导览带在 320/390/430px 的中英文下均无文字裁切；选择日期后第 2 步正确成为 `aria-current="step"`，预约业务状态未改变。
- `/shop` 中文移动端四分类单行等分；英文移动端使用两列两行。320/390/430px 均为 `scrollWidth === clientWidth`，按钮文字完整，标题区无浮卡背景、阴影或点阵。
- 前端全量 Vitest `49` 文件 / `263` 项、类型检查、生产构建、构建预算、`qa:pointer-pages 32/32` 与 `git diff --check` 通过。
- 本轮未发布 PocketBay，实体 iOS/Android、系统强制颜色和真实触控惯性仍待验收；未提交真实预约、未执行购物车结算。
