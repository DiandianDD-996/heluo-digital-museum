# 2026-08-15 控件与路线卡片视觉收口计划

## 目标

修复用户在 `/explore`、`/appointment`、`/shop`、`/admin` 和 `/admin/operations` 真实页面标注的控件层级问题：搜索框聚焦不再出现大框套小框，主题脉络与参观路线改为更清晰的编辑式路线板，商城分类与后台运营标签/筛选具备一致、可读、可操作的状态反馈，商品卡只保留一层可见卡面。

## 关联需求

- `F-01/F-02/F-03`：公开内容浏览、搜索与双主题视觉一致性。
- `F-06/F-08`：后台内容与运营工作台的任务效率和状态反馈。
- `F-09`：文创商城分类浏览。
- `F-11`：预约流程的路线与摘要提示。
- `N-03/N-06`：响应式、键盘焦点、减少动效/高对比度降级。

## 范围与不变项

- 范围：`MuseumSearchField`、Explore 主题脉络、预约路线 SVG、商城分类导航与商品卡材质、后台内容状态筛选、运营标签/筛选工具条。
- 不改 API、路由、鉴权、搜索/筛选/分页、预约/订单状态机、商品数据和 Three.js 生命周期。
- 不新增运行时图片；继续复用现有语义令牌、图标库和双主题 CSS 合同。

## 实施步骤

1. 梳理搜索字段的网格、焦点 ring 与清除/提交按钮尺寸，使外层控制槽只有一层可见边界。
2. 将 Explore 主题脉络做成安静的“地图索引”路线板，用节点、分段标签和轻量内沿替代抢眼长线条。
3. 将预约路线 SVG 收敛为分层路径和编号节点，补充路线板的标题/说明层级，保持深浅主题可读。
4. 将商城分类和后台 tabs/filter 统一为紧凑分段控件；后台筛选在桌面与移动端分组排列，原生 `select` 保持语义和键盘行为。
5. 桌面端让商城商品外层 `article` 仅承担布局，由 `.product-copy` 独占卡面；移动端保留整行外卡，让信息区透明并只保留分隔线，消除两种布局中的重复外框。
6. 添加 CSS/DOM 契约测试，运行类型检查、相关测试、构建和真实 Docker 页面复核。

## 验收标准

- 搜索框获取焦点时不出现相互错位的外框；控件高度、输入、清除、提交按钮在桌面/移动端稳定，焦点状态清晰。
- Explore 主题脉络和预约路线在浅/深主题下都具备明确的标题、节点、路径和辅助文字，视觉不依赖一条粗线或纯颜色。
- 商城分类按钮和后台 tabs/filter 有 default、hover、focus、active、disabled 状态，触摸目标至少 `44px`，长标签不溢出。
- 商城三张商品卡均只有一层可见边框、背景和阴影，卡片内容与加入购物车交互不变。
- `/explore`、`/appointment`、`/shop`、`/admin`、`/admin/operations` 在目标桌面与 `390x844` 无横向溢出，原有业务交互保持可用。
