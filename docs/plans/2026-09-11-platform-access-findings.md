## 已复现结果

| 对象 | 观察结果 | 影响及边界 |
|---|---|---|
| 休眠入口 | 普通 HTTP 四路径 204；浏览器显示平台休眠页 | 两种请求呈现不同，不能把空响应一律归因于应用后端 |
| 公开唤醒 | 点击一次“唤醒并继续”后四路径恢复 200，浏览器内嵌应用可见 | 证明当前公开唤醒可用；没有平台启动日志，无法追溯所有历史 204 |

| sitemap | 当前线上 401、`AUTH_REQUIRED` | 本地两拓扑的修复尚未部署，不能声称线上已修复 |
| 手机平台浮层 | 390×844 展项截图中平台反馈气泡覆盖导览区域上沿 | 应用 CSS 不能管理跨域外壳。需平台配置能力或最终实际遮挡验收，不以移除本地控件掩盖问题 |

## 外壳能力核对

搜索补验使用源码实际参数 `q`：`/explore?q=%E9%9D%92%E9%93%9C`。打开后显示 3 条青铜结果，搜索框值“青铜”；刷新外层仍保留相同搜索值。证据 `artifacts/holistic/platform-routing-1789060679975/summary.json`。这证明正确的具体 URL 可分享/刷新，不解决从首页站内导航时外层 URL 不更新的问题。

从实际公开 HTML 提取的路由脚本只保存了公开程序片段及 SHA-256，没有归档临时握手 token。脚本包含外层 hashchange→内层 URL 和 `pocketbay:login-required` 消息处理；未看到通用的内层路由→外层 history 同步处理。这是当前响应代码的观察，不等于对平台所有能力的全面断言。

不能直接在 Vue 中发送一个自行发明的 postMessage 就宣称平台地址会同步。若平台有正式桥接协议，需确认来源/目标 origin、消息结构、路径白名单和前进后退行为后再实施。跨域边界不允许应用直接写外层 history。

## 下一步可执行边界

1. 本地 sitemap/robots 修复保持现有精确匿名规则，随最终版本一起进入独立授权发布；上线后重新检查外层和应用层。
2. 平台控制台或官方资料中核对是否可关闭托管外壳、允许搜索索引、配置路由桥接与反馈浮层。当前已登录浏览器连接不可用，未确认具体配置存在，不自动购买套餐或迁移域名。
3. 若平台不提供这些能力，向用户说明托管限制，再选择接受限制或独立托管；长期架构选择另记 ADR。
4. 当前进行 10 分钟/21 轮轻量采样，检查首页实际入口、health/ready JSON、公开数据及首尾资源指纹。采样期间的请求可能影响平台空闲判断，结果只能代表唤醒后的短期访问，不能替代空闲冷启动或 SLA。
