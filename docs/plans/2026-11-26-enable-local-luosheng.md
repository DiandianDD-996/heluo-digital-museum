# 启用本地洛笙向导

- 目标：在 localhost:8088 启用洛笙按钮和青铜鼎馆藏问答；关联 F-05 与洛笙可选扩展。不改变公网部署。
- 范围：更新 MySQL Compose 的只读证据卡挂载及本地忽略配置；前端构建开关启用；后端向导启用、模型明确关闭。沿用原 MySQL 数据卷、端口及凭据。
- 步骤：核对 Vite 与 Spring 双开关/证据卡校验 → Compose 只读挂载 content/luosheng → 更新本地 .env 与安全示例/部署说明 → 仅重建前端 → 重启前后端 → 验收 API、入口及一轮真实归档回答/引文。
- 验收：访客从首页打开“问洛笙”，获得回答并能展开证据引文。后端 readiness UP，签核资料按 SHA-256 和最低版本校验。
- 风险：应用容器重启时本地页面短暂不可用。签核摘要不匹配或资源路径不可读会影响证据卡展示。

## 验证结果

- `docker compose config` 展开结果确认前端及后端开关均为 true、模型开关为 false、三条签核路径落在只读 `/run/luosheng` 挂载中。
- Vite 生产构建通过；前端与后端以新 Compose 配置重建/重启，MySQL 服务及既有数据卷保持运行。
- Playwright 在首页看见“问洛笙”并打开面板，实际提交青铜鼎鼎耳问题；聊天 API HTTP 200，回答徽标为“馆藏资料直出”，展开来源为 `LS-DING-EARS · v3`。没有调用模型。
- `/api/v1/ready` 返回 UP，证据预设 API HTTP 200；挂载内容只读。不是外部模型输出或公网验收。
