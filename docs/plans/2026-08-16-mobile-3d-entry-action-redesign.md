# 移动端 3D 入口操作区重设计

## 1. 目标

修复移动端 3D 展项海报状态中“查看展项信息”覆盖“进入互动 3D”的问题，让主操作完整可见、易于触达，并在进入 3D 后继续提供不遮挡模型或导览的展项信息入口。

关联需求：`F-05`、`F-12`、`F-14`、`N-03`、`N-06`。

## 2. 影响范围

- `frontend/src/views/ExhibitDetailView.vue`
- `frontend/src/assets/route-exhibit-detail-legacy.css`
- `frontend/src/views/ExhibitDetailView.spec.ts`
- 项目状态与需求追踪记录

不修改 API、路由、鉴权、模型来源、移动模型选择、Three.js 生命周期、点云参数、相机、导览状态机或桌面展项布局。

## 3. 设计方案

- 海报状态：将“进入互动 3D”和“查看展项信息”合并为海报底部的单一操作区，主操作占据更高视觉权重，两个按钮保持至少 `48px` 触控高度。
- 启动状态：操作区显示明确的准备中状态，不叠加第二个悬浮入口。
- 运行状态：展项信息入口移至场景右上角、返回按钮下方，避开模型主体、左侧工具栏和底部导览面板。
- 中英文长文案允许换行，不使用固定单行宽度；浅色、深色和可见键盘焦点均保留。

## 4. 实施步骤

1. 为海报状态增加语义化操作容器和图标，复用既有启动与 BottomSheet 行为。
2. 仅在 Viewer 就绪后显示独立移动信息入口。
3. 以页面级移动端选择器重排海报说明和操作区，并为 `320–760px` 保持稳定尺寸。
4. 增加组件结构和交互测试，验证两个操作不会再次分离成重叠浮层。
5. 运行专项测试、全量前端测试、类型检查、生产构建、Docker 与真实移动视口回归。
6. 覆盖部署 PocketBay 项目 `#329`，复核线上移动入口与 3D 启动流程。

## 5. 验收标准

- `320×800`、`390×844`、`412×915` 中“进入互动 3D”完整可见且可点击。
- 海报状态的两个操作互不重叠，也不被导览面板覆盖。
- 点击展项信息能打开 BottomSheet；点击主操作能使用移动 GLB 启动 Viewer。
- Viewer 就绪后，信息入口不覆盖底部导览、模式切换或视角按钮。
- 页面无横向溢出，控制台无新增 warning/error；桌面布局和点云行为不变。

## 6. 风险

- 路由样式存在多层历史覆盖，必须在最终 Docker/PocketBay 页面检查计算样式和实际矩形位置。
- 移动浏览器地址栏和系统安全区会改变可见高度，因此不能依赖单一固定底部偏移。
- 实体手机的浏览器工具栏高度仍需现场补验。

## 7. 验证结果

- 海报状态已改为同一操作面板：主操作“进入互动 3D”与次操作“查看展项信息”按文档流纵向排列，移动端触控高度均为 `50px`，不再使用两组竞争的绝对定位。
- Viewer 启动过程中不显示第二个悬浮信息入口；进入 `ready` 后，信息入口显示在右上角“返回展厅”下方，并保持 BottomSheet 的 `aria-expanded` 状态同步。
- 专项测试 `2` 个文件 / `13` 项、前端全量 `44` 个文件 / `245` 项、`corepack pnpm typecheck`、生产构建、后端 Maven `28/28`、Compose 重建和传统 Docker builder 均通过。
- 本地正式页面在 `320x800`、`390x844`、`412x915` 完成海报和 ready 状态回归：两个海报操作互不遮挡，ready 状态信息入口与返回按钮、工具区、Dock 的重叠面积均为 `0`，横向溢出为 `0`，BottomSheet 可打开，Canvas 为 `ready/running`。
- PocketBay 项目 `#329` 已覆盖为 deployment 对应 release `498`，平台返回 `next_action=done`、`project_status=running`，活动地址为 `https://heluo.pocketbay.app`。线上三个移动尺寸的 ready 状态重叠面积均为 `0`，BottomSheet 可打开；首页、深层路由和 health 为 HTTP `200`，移动 GLB Range 为 `206 bytes 0-1023/837720`。
- 已知 Three.js `X4122` 浮点精度 warning 仍保留；未发现新增应用错误。实体手机、系统浏览器工具栏安全区、触控笔、强制颜色和中低端 GPU 长时间帧率仍待现场验收。
