# 全站深色主题融合精修计划

## 目标

在不改变路由、API、权限、预约、商城、模拟支付和 Three.js 状态机的前提下，系统性修复深色模式中“页面已经变暗，但图片、卡片和工作区仍像浅色模块拼接”的视觉割裂，使前台与后台形成完整、克制、高端的河洛数字博物馆体验。

## 关联需求

- F-14：前后台可切换并持久化深色主题。
- N-03：桌面与移动端可用、可读、无关键横向溢出。
- N-06：保持可维护的共享设计令牌与组件契约。

## 影响范围

- `frontend/src/assets/main.css`：补充深色画布、图片舞台、卡片、表单、导航和后台工作区主题覆盖。
- `frontend/public/media/editorial/museum-corridor-dark-image2.webp`：深色首页专用无文字环境素材。
- `frontend/public/media/editorial/README.md`：登记新素材来源与用途。
- `DESIGN.md`：补充双主题图片与深色层级约束。
- `frontend/src/assets/darkThemeCohesion.spec.ts`：锁定主题素材、核心路由和后台覆盖契约。
- `PROJECT_STATUS.md`、`docs/01-requirements-traceability.md`：记录完成范围与验证结果。

## 实施步骤

1. 复核全局主题令牌、三层玻璃契约和页面局部硬编码浅色样式。
2. 建立深色画布、媒体舞台、图片边缘、输入控件与卡片层级令牌。
3. 优化首页、馆藏、展厅、详情、预约、商城、登录和个人中心的深色视觉。
4. 优化后台内容与运营工作台的页面底色、工具栏、表单、列表、状态和操作按钮。
5. 使用外置浏览器中已登录的 ChatGPT Plus Image 2 生成首页深色专用环境图，并压缩为 WebP。
6. 运行主题专项测试、全量前端测试、类型检查、生产构建、页面映射和真实浏览器双主题回归。

## 验收标准

- 深色首页使用专用夜间环境图，标题、说明、路线卡与背景形成清晰层级。
- 馆藏与展厅中的浅底文物图被统一放入深色媒体舞台，不出现突兀白块或文字失读。
- 预约、商城、登录、详情页中的表单、摘要、空状态与操作控件在深色主题下可读且状态一致。
- 后台页面底色、页头、统计、标签、表单、记录与运营看板属于同一深色工作台，而不是白底页面上的深色卡片。
- 浅色主题外观和业务功能不回归；主题刷新保持；桌面与 `390x844` 无横向溢出和控制台错误。

## 风险

- 深色覆盖位于大型历史 CSS 文件尾部，必须使用主题令牌和有限的结构选择器，避免继续积累页面级颜色分叉。
- 文物图片本身包含浅色拍摄背景，不能全局强制反相或重度调色；仅通过媒体舞台、边缘遮罩和轻度亮度校准融合。
- Image 2 素材只承担环境，不包含文字或业务信息；移动端仍需保证标题与操作不依赖图片细节。
