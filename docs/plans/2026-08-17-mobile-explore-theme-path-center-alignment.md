# 移动端 Explore 主题路径中心圆稳定对齐

## 1. 目标

修复 `/explore` 主题路径在不同移动端宽度下，河线主圆与罗盘中心发生纵向漂移的问题，使 320–760px 范围内两层始终使用同一坐标系和视觉圆心。

关联需求：`F-01`、`F-02`、`F-12`、`F-14`、`N-03`、`N-06`。

## 2. 根因

移动端河线素材使用 `width: 108%; height: auto` 随容器宽度缩放，而罗盘使用 `top: 27%`、`left: 55%` 相对固定高度的 `.collection-theme-path__river-layer` 定位。两层缩放基准不同，纵向偏差随设备宽度变化：线上实测 320px 为 `+25.136px`、390px 为 `+7.195px`、430px 为 `-3.059px`。

## 3. 影响范围

- `frontend/src/views/ExploreView.vue`
- `frontend/src/assets/control-surface-polish.css`
- `frontend/src/assets/ExploreMobileThemePathAlignment.spec.ts`
- `PROJECT_STATUS.md`
- `docs/01-requirements-traceability.md`

不修改主题路径文字、生产图片、搜索/筛选/分页、API、路由、鉴权或其他业务状态机。

## 4. 实施方案

- 在河线和罗盘外增加 `.collection-theme-path__river-artwork`，让两张素材共享定位上下文。
- 移动端 artwork 使用生产河线的 `1500 / 562` 固定宽高比和现有 `108%/-4%` 视觉铺幅。
- 罗盘继续使用已校准的 `--theme-path-main-node-x: 54.067%`、`--theme-path-main-node-y: 63.345%`，不再使用独立的移动端 `55%/27%` 近似值。
- 五个文字节点继续使用现有移动端列表布局，不改变可读性或触控行为。

## 5. 验收标准

- 320、375、390、414、430 和 760px 下，河线主圆与罗盘视觉锚点的横纵偏差均不超过 `0.5px`。
- 中英文、浅色/深色使用相同几何；五个标签无重叠，页面无横向溢出。
- 桌面河线、罗盘与第三节点原有对齐不回归。
- 专项/全量测试、类型检查、生产构建、页面映射和 `git diff --check` 通过。

## 6. 风险

- 该组件包含多层绝对定位与懒加载图片，需在素材完成解码后测量，不能用未加载时的 `0px` 图片高度判断。
- 浏览器视口模拟不替代实体手机的缩放、字体渲染和系统辅助模式验收。

## 7. 验证结果

- 线上旧版偏差已复现：320px 为 `+25.136px`、390px 为 `+7.195px`、430px 为 `-3.059px`。
- 本地修复后，320/375/390/414/430/760px 的横纵圆心偏差均低于 `0.01px`；六档均无标签重叠或页面横向溢出，430px 英文深色同样通过。
- 前端全量 Vitest `48` 文件 / `260` 项、类型检查、生产构建、构建预算、`qa:pointer-pages 32/32` 与任务文件 `git diff --check` 通过。
- 已随 PocketBay deployment `1129` / release `634` 发布并进入 `done/running`。线上 320/375/390/414/430px 在图片解码后按素材视觉锚点测量，横纵偏差均低于 `0.02px`；五档标签重叠和页面横向溢出均为 `0`。
- 罗盘图片为 `480×477`，既有 `translate(-50%, -48.85%)` 用于素材视觉中心校准；其 DOM 外接框几何中心固定低约 `1.32px`，不随视口变化，不是本次修复前的宽度相关漂移。
- 线上页面映射审计 `32/32` 通过，`/explore` 与 health 为 `200/UP`。用户提供的实体手机截图来自旧 release；release `634` 仍需在同一台实体手机上刷新复验，系统强制颜色和真实慢网仍待验收。
