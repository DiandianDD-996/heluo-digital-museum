# 数字文物扫描场鼠标动效精修

## 目标

在保留现有 `6px` 青玉光点、四个公开页局部 Canvas 和全部输入/性能降级规则的基础上，将当前均匀“点阵推开”效果升级为具有数字博物馆识别度的“文物扫描场”：鼠标附近出现克制的拓扑连线、环形能量波与青玉/古铜扫描刻度，静止后停止计算，内容和操作仍是主角。

## 关联需求

- F-01 / F-02 / F-03 / F-05 / F-09：公开前台品牌体验与内容探索。
- N-03：响应式、触控、媒体偏好与无障碍降级。
- N-06：前端性能、按需帧循环和资源释放。

## 影响范围

- `PointerDotField` Canvas 绘制与状态标记。
- 点阵几何纯函数、参数和单元测试。
- 指针视觉契约测试、性能审计和页面映射回归。
- 项目状态、需求追踪与本实施计划。

不修改后端、REST API、路由、鉴权、预约、购物车、支付、Three.js 展项或后台；不新增依赖，不扩大到整页连续动画。

## 设计策略

1. **唯一签名动作**：鼠标经过点阵时形成“环形扫描波”，不是常见霓虹拖尾或粒子烟花。
2. **数字文物语义**：青玉节点代表采样点，古铜节点与短连线代表文物数据切片；扫描刻度采用断续圆弧和四向校准线。
3. **层级克制**：基础点阵更小、更疏、更低对比；仅鼠标邻域提高节点尺度和连线清晰度，避免覆盖标题与文物主体。
4. **性能边界**：继续使用共享非响应式坐标与单一 RAF；只绘制相邻网格短线，不做全点两两距离计算；离开、离屏、静止、后台或降级后零持续帧。
5. **可访问降级**：减少动态、高对比度、强制颜色、粗指针和触控笔维持既有关闭规则；减少透明度模式保留低对比实色点阵与实色扫描反馈。

## 实施步骤

1. 扩展点阵节点的网格坐标、活动能量与回弹状态，加入径向波峰和轻微切向流动。
2. 重写 Canvas 分层绘制：静态底点 → 局部拓扑短线 → 高能节点 → 扫描圆弧/校准刻度。
3. 增加 `data-effect` / `data-scanner` 可观测状态，便于自动化确认生产页面使用新效果。
4. 更新纯函数、组件和 CSS 契约测试，并保持性能体积门禁。
5. 运行前端测试、类型检查、构建、指针性能/体积、四页多尺寸映射和浏览器目视回归。
6. 重建 Docker 前端镜像，检查运行资产、首页和 API health，再更新项目文档并审查 diff。

## 验收标准

- 四个既定主视觉仍各只有一个 Canvas，鼠标附近可见扫描环、局部拓扑和青玉/古铜高能节点。
- 基础点阵不再像覆盖全屏的高对比网格；标题、按钮、图片和玻璃看板不被遮挡或截获点击。
- 节点位移、缩放和能量均有上限，动画仅使用 Canvas 绘制且不触发布局。
- 鼠标静止后共享 RAF 归零；离开主视觉后扫描刻度消失、点阵回到基线并停止 RAF。
- 减少透明度模式使用实色低对比底点和实色高能反馈；其他约束输入/媒体模式保持静态或系统指针。
- 单元测试、类型检查、生产构建、`perf:pointer`、`perf:pointer-size`、`qa:pointer-pages`、Docker 与浏览器实页验证通过。

## 风险

- 扫描线过亮会压过博物馆内容：基础层使用低对比色，仅局部能量区增强，扫描圆弧尺寸限定在光标附近。
- 连线增加 Canvas 绘制成本：只连接水平/垂直相邻节点且设能量阈值，不做全局邻近搜索。
- Windows 减少透明度偏好可能改变观感：单独维护实色 palette，并在实际运行环境复验。

## 验证结果

- 实现完成：点阵由均匀推开升级为“静态采样点 → 局部水平/垂直拓扑 → 环形高能节点 → 双材质扫描刻度”四层绘制；新增轻微切向流动，让网格呈现数字采样面而不是普通气泡排斥。
- 视觉收口：间距由 `18px` 调整为 `22px`，青玉/古铜基础点缩小并降低对比；高能节点最大 `2.05` 倍、位移最大 `20px`，扫描圆弧限定在光标附近。Windows 减少透明度模式改用低对比实色底点与深色实色高能层。
- 可观测性：Canvas 暴露 `data-effect="artifact-scan"` 与 `data-scanner="tracking|idle"`；生产首页实测为 `artifact-scan / tracking / active / opaque`，运行入口为 `/assets/index-Dq1almdf.js`。
- `pnpm test`：23 个测试文件、79 项全部通过；新增扫描波能量峰、切向位移、活动能量回弹和组件扫描状态断言。
- `pnpm typecheck`：通过。
- `pnpm build`：通过；仅有既有 Three.js `734.33 kB / 189.46 kB gzip` 路由分包警告。
- `pnpm perf:pointer-size`：通过，交互代码 `16,975 B minified / 6,225 B gzip`，低于 `18,000 B / 7,000 B` 预算，无布局属性 transition。
- `HELUO_PERF_DURATION_MS=2000 pnpm perf:pointer`：16 项门禁全部通过；普通页指针派发均值 `0.12ms`、RAF 回调均值 `0.222ms`，4x CPU 可降至 static，后台暂停、媒体偏好、200% 视口、pen/touch 和 Three.js 边界均通过。
- `pnpm qa:pointer-pages`：首页、馆藏、展厅列表和商城 × 8 档尺寸共 32 组通过；9 项门禁全部通过，无横向溢出、控件裁切或点击拦截，Canvas 有像素且 full 档可激活。第一次与性能审计串联执行时后续 Windows Chrome 进程异常退出，单独复跑页面映射通过。
- Docker：使用 `--no-cache` 构建并强制替换前端容器；运行容器与 `deploy-frontend:latest` 均为 `sha256:d10de48b1a9bea6180c5dd003e6ec1ca5ff0c4ad2c41e71b975b1ef38f47de4d`。首页和 API health 均为 `200`，health 数据为 `UP`。
- 浏览器：`819×898` 实页及自动化 `1440×900` 截图确认基础点阵更安静、局部扫描拓扑可见、标题/青铜鼎/路线看板层级未被破坏，页面横向溢出为 `0`；Impeccable detector 返回 `[]`。
- 未验证：本轮未在真实手机、实体触控笔和高刷鼠标上重复人工手感测试；对应触摸/pen/性能降级已由自动化覆盖。未改后端业务代码，因此未重复运行 Maven 测试。
