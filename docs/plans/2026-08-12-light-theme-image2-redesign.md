# 浅色模式 Image 2 全站改造计划

## 目标

以当前正式浏览器页面为唯一业务与布局基线，先通过网页版 ChatGPT / Image 2 生成浅色“日间月白展厅”的全页及控件参考图，经用户确认后再改造前端。重点改善浅色模式过白过亮、表面层级不足、卡片与控件不够突出等问题。

## 关联需求

`F-01`、`F-03`、`F-05`、`F-06`、`F-08`、`F-09`、`F-12`、`F-13`、`F-14`、`N-03`、`N-06`。

## 范围与约束

- 覆盖公开前台、账户、3D 展厅、内容后台与运营后台。
- 保留“河洛纸墨”、东方编辑策展、青玉/青铜/朱砂低面积强调。
- 不改变 API、路由、权限、预约/订单状态机、模拟支付、Three.js 与点云行为。
- Image 2 参考图中的文字和业务 UI 最终仍由 Vue DOM 实现，不将生成图内文字当作生产内容。
- 输入图、生成结果和最终生产素材分开记账；不覆盖现有资产。

## 设计方向

1. 建立四级浅色材质：冷月白画布、浅青灰分区、低彩玉釉内容面、略深的浮起控件。
2. 卡片以图像和内容为主，只有可交互卡片拥有 `hover/press`；静态看板不抬升。
3. 搜索框保持单层边界，改为微嵌入的“玉石槽”；焦点态用青玉边框和柔和外环。
4. 复选框、分段控件、按钮和状态徽标共享同一几何与材质语言，只在当前态使用低面积古铜光沿。
5. 动效使用无弹跳的 `180–240ms` ease-out；按压及时反馈，减少动态下只保留短淡入和颜色变化。

## Image 2 输入与产出

### 真实页面输入

- 桌面 `1440×900`：首页、探索馆藏、数字展厅列表、预约、商城、登录/账户、内容后台、运营后台。
- 移动 `390×844`：首页、探索馆藏、预约、商城、登录/账户、后台记录卡。
- 控件近景：卡片、搜索+筛选、按钮全状态、复选框/分段控件、表单、状态/空态/错误态。

### 参考图批次

1. `A-system-board`：浅色四级材质和共享控件状态板。
2. `B-public-desktop`：首页、探索、展厅、商城的桌面优化。
3. `C-task-desktop`：预约、登录、账户的任务页优化。
4. `D-admin-desktop`：内容与运营后台紧凑工作台。
5. `E-mobile`：关键页面 `390×844` 响应式参考。
6. `F-assets`：只在参考图确认后，独立生成无文字背景/媒体舞台等位图资产。

## 实施波次

1. 基础 token、三层玻璃和共享控件。
2. 首页、探索、展厅列表和详情。
3. 商城、预约、登录和账户。
4. 内容后台和运营后台。
5. 全路由回归、对比度、辅助功能和资产优化。

## 验收标准

- 浅色页面不再出现大面积纯白或临时 `white/#fff`造成的断层。
- 相邻画布、分区、内容面和控件面在真实页面上可辨别，但不变成卡片墙。
- 搜索、按钮、复选、筛选和卡片的默认、hover、focus、active、disabled、loading、error/success 状态完整。
- 正文对比度不低于 `4.5:1`，大文字和关键边界不低于 `3:1`。
- `320/375/414/768/1440px` 无横向溢出、文字裁切或底部导航遮挡。
- 键盘焦点可见；`prefers-reduced-motion`、减少透明度、增强对比度和强制颜色模式有降级。
- 前端类型检查、全量测试、生产构建、页面门禁、Docker 正式 URL 与关键业务流程通过。

## 风险

- `main.css` 含有多轮历史页面覆盖，需先用可视基线和契约测试锁定级联，再分波清理。
- Image 2 参考图可能改变文字或发明功能，仅采纳材质、色彩、光影、布局与交互表达，业务以真实 Vue DOM 为准。
- 相关路由可能需要不同角色登录；截图只使用本地已有会话和被忽略配置，不归档凭据。
