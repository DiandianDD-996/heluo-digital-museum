# 移动端优化汇总留痕

**日期：** 2026-08-17  
**性质：** 已实施工作的汇总记录，不包含新的业务需求或代码改动。  
**关联需求：** `F-01`、`F-03`、`F-05`、`F-06`、`F-08`、`F-09`、`F-12`、`F-14`、`N-03`、`N-04`、`N-05`、`N-06`。

## 1. 目标与边界

本记录说明当前项目如何优化移动端的可用性、性能和可访问性，并保留可复查的验证证据。

- 优化目标：在 `320px` 至 `760px` 的常见移动视口中，保证核心页面可浏览、可触达、无页面级横向溢出；3D 资源不阻塞普通浏览；浅深主题和中英文保持可读。
- 不变边界：未改变 API、路由、鉴权、预约校验、订单/支付状态机、3D 展项内容和桌面端业务流程。
- 发布状态：PocketBay 项目 `#329 / heluo` 的 release `639` 已运行；线上已完成关键移动尺寸回归。
- 证据边界：浏览器模拟视口、线上 HTTP 和自动性能审计已通过；实体 iOS/Android、真实键盘/安全区、真实网络与中低端 GPU 不是本记录的已完成项。

## 2. 优化方法总览

| 方向 | 当前做法 | 用户收益 |
|---|---|---|
| 响应式布局 | 以 `760px` 为移动端布局分界，针对 `320/375/390/393/412/414/430px` 复核；内容改为单列、等分或可横向访问的轨道，避免把桌面卡片等比缩小。 | 窄屏内容不裁切、不产生页面级横向滚动。 |
| 顶部与底部操作 | Header 工具入口统一为 `44x44px`；窄屏英文品牌可收缩、省略，账户入口使用带可访问名称的图标；底部导航、购物车和弹层均计入安全区。 | 常用操作可点击，刘海屏和浏览器底栏不遮挡内容。 |
| 预约流程 | 原生日期下拉在移动端改为未来 14 天日期卡带；四张卡稳定可见，时段、禁用/选中态和填写入口在页面上直接反馈；表单置于专属 BottomSheet。 | 不必打开系统下拉框寻找日期，预约步骤和当前状态更直观。 |
| 公开浏览与商城 | Explore、首页和商城在移动端减少非操作性装饰、使用单列或稳定分类栅格；Explore 河线与罗盘共用坐标层；中文商城四等分，英文两列两行。 | 搜索、筛选、分类和阅读保持可扫描，视觉锚点不随宽度漂移。 |
| 触控与辅助功能 | 关键控件保持最小触控尺寸，日期轨道支持触控滚动/吸附、焦点环与按压反馈；使用 `safe-area-inset-bottom`、`100dvh`、减少动态和强制颜色等降级规则。 | 触控、键盘和系统辅助偏好下仍保留核心操作。 |
| 3D 首帧与交互 | 移动/粗指针/省流量/慢网/低内存环境先展示封面和说明，用户主动进入互动 3D；优先选择移动 GLB，五视角按可用宽度等分或横向可访问；退出时释放场景资源。 | 普通浏览不被 WebGL 和大模型阻塞，进入 3D 后仍能使用全部视角与控制。 |
| 3D 渲染质量 | 移动端限制 DPR，使用移动点云预算；深色点云采用独立青玉/古铜配色和较大点径，主题切换只同步 Shader uniform，不重建几何。 | 在移动深色场景中仍可辨识鼎身、双耳和三足，降低不必要的渲染负担。 |
| 传输与缓存 | 使用响应式图片、路由按需资源、移动 GLB、HTML 重新验证、哈希静态资源长期缓存和私有 API `no-store`。 | 冷启动更轻，二次访问可复用缓存，同时不缓存私有响应。 |

## 3. 已完成的页面级优化

| 页面/模块 | 已解决问题 | 已保留的行为 | 主要证据 |
|---|---|---|---|
| 公共 Header | 英文账户文字会在窄屏向右裁切。现在品牌区可收缩，主题、语言、账户为三个稳定 `44x44px` 工具槽，账户图标保留 `aria-label`。 | 主题、语言、登录/账户语义与路由不变。 | `2026-08-17-mobile-english-account-header-fit.md`；正式 320/390/393/430px 共 16 组页面回归通过。 |
| Explore | 河线和罗盘使用不同缩放基准，圆心会随设备宽度漂移。现在复用同一 artwork 坐标层、固定素材比例与校准圆心。 | 搜索、筛选、分页、详情跳转不变。 | `2026-08-17-mobile-explore-theme-path-center-alignment.md`；本地偏差小于 `0.01px`、线上小于 `0.02px`。 |
| 预约 | 日期信息隐藏在下拉框中，步骤、场馆信息和填写表单在移动端层级分散。现在提供日期卡带、单轨步骤、时段区、禁用提交态、专属 BottomSheet 和 `44x44px` 人数步进器。 | 后端时段来源、自动选择首个可用时段、表单校验、幂等提交和状态机不变。 | `2026-08-17-mobile-appointment-calendar-polish.md`、`2026-08-17-mobile-appointment-page-detail-redesign.md`、`2026-08-17-mobile-appointment-progress-shop-intro-polish.md`。 |
| 商城 | 移动标题区有多层浮卡，分类会出现半个按钮、滚动或文字裁切。现在标题区去除冗余容器，中文四等分单行，英文两列两行。 | 商品分类、购物车与模拟支付流程不变。 | `2026-08-17-mobile-appointment-progress-shop-intro-polish.md`；320/390/430px 无分类溢出。 |
| 3D 入口与视角 | 入口操作会相互遮挡；391--760px 的第五个视角初始被裁切。现在入口按文档流排列，430/412px 五视角等分完整显示，390px 以下保留横向访问。 | 实体/点云模式、相机预设、交互和模型内容不变。 | `2026-08-16-mobile-3d-entry-action-redesign.md`、`2026-08-17-mobile-exhibit-view-thumbnails.md`。 |
| 3D 深色点云 | 旧深色点云与背景对比不足。现在使用移动深色专用配色、`1.16` 点径、墨绿暗厅和低亮展台；点数仍为 `18,000`、DPR 上限仍为 `1.25`。 | 移动浅色点径、桌面参数、GLB、采样、相机和资源释放不变。 | `2026-08-17-mobile-dark-point-cloud-polish.md`；正式 `390x844` 实页可辨识完整鼎形。 |

## 4. 性能与线上验证证据

已实施 `2026-08-16-pocketbay-mobile-performance-optimization.md` 中的移动性能合同，并保留 `artifacts/performance/mobile-summary.json` 作为机器可读取证据。

- 采用 6 条路由、Fast 4G/Slow 4G、冷/暖缓存的 `24` 次移动访问审计；线上 31 项自动门禁全部通过。
- Fast 4G 首页冷访问：传输 `274.4 KiB`，TTFB `269ms`，LCP `1688ms`。
- 3D 在启动前：`355.6 KiB`；用户启动后新增：`1038.7 KiB`；移动 GLB：`819.1 KiB`；点击到完整首帧：`2977ms`。
- Slow 4G 的 Explore 冷访问 LCP `4672ms`、3D 点击到首帧 `6087ms`，当前作为非阻断观察值保留，不等同于实体网络验收。
- 缓存合同已验证：HTML `no-cache, must-revalidate`，带哈希静态资源 `public, max-age=31536000, immutable`，未登录私有接口为 `401 + no-store`，移动 GLB 支持 Range 请求。
- 线上关键页面映射 `32/32` 通过；Explore、预约、商城和 3D 已在 `320/375/390/414/430px` 的相关组合检查横向溢出、裁切、视觉锚点和关键触控状态。

## 5. 验收结论

### 已验证

- 前端类型检查、Vitest、生产构建、构建预算、`qa:pointer-pages 32/32` 和相关专项测试已在各实施记录中通过。
- 正式 PocketBay 页面、健康接口和关键移动布局通过线上回归；release `639` 为当前运行版本。
- 预约日期/时段、商城分类、公共 Header、Explore 主题路径、3D 入口/五视角/点云等关键移动状态已在模拟视口和线上页面验证。

### 未验证与风险

- 原实体 iPhone/Android 的浏览器工具栏、安全区、系统字体缩放、真实软键盘、触控惯性与触控笔。
- 系统强制颜色/高对比度、OLED/LCD 实际亮度与系统色彩增强。
- 三运营商真实慢网、低端 CPU/GPU 的 3D 长时间帧率、真实 INP。
- 实体设备上的真实预约提交、购物车结算、后台 CRUD 和真实 SMTP。

这些项目保持“待验收”，不能因浏览器模拟视口或自动审计通过而标记为完成。

## 6. 后续复验清单

1. 在至少一台 iOS 和一台 Android 真机上，以 320--430px 等效宽度复验 Header、Explore、预约、商城和 3D。
2. 分别开启系统字体缩放、深色模式、减少动态和高对比度/强制颜色，确认无裁切、无不可点击控件。
3. 使用真实移动网络完成一次预约和一次购物车模拟支付，记录提交、错误提示和返回路径。
4. 在中低端设备连续运行 3D 5 分钟，记录首帧、交互帧率、发热和退出后内存恢复情况。
5. 将每次真机结果追加到对应实施合同，不覆盖本汇总的历史证据。
