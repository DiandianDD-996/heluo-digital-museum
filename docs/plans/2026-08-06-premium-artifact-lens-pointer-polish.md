# 高级文物数据透镜鼠标动效精修

## 目标

针对上一版“数字文物扫描场”在实际页面中出现的大面积方格拓扑、局部形变过强和视觉竞争问题，收敛为更克制、更精密的“文物数据透镜”：基础采样点退后，鼠标附近只保留柔和环形节点响应、非对称椭圆轨道和少量古铜校准节点，让科技感来自精度与层次，而不是网格数量。

## 关联需求

- F-01 / F-02 / F-03 / F-05 / F-09：公开前台品牌体验与内容探索。
- N-03：响应式、媒体偏好和输入降级。
- N-06：指针热路径、按需 RAF 与代码体积预算。

## 根因与设计修正

- **概念偏差**：相邻节点水平/垂直全连接形成“变形铁丝网”，更像通用科幻 HUD，不符合河洛纸墨的安静策展气质。
- **层级偏差**：高能区域过大、连线密度过高，遮挡青铜鼎和标题，动效成为主角。
- **修正方向**：删除方格拓扑；点阵间距加疏、节点缩小、位移与缩放收口；以三层非同心断续椭圆、方向缓动和三个古铜采样节点构成唯一焦点。

## 影响范围

- `PointerDotField` Canvas 绘制、方向状态和可观测效果名称。
- 点阵纯函数参数与单元测试。
- 项目状态、需求追踪和本计划。

不修改页面结构、路由、业务 API、Three.js、表单、后台或后端；不新增依赖。

## 实施步骤

1. 删除活动节点的矩形拓扑连接，移除网格列数和连接阈值状态。
2. 收紧点阵密度、位移、切向流动、能量波宽度和最大缩放。
3. 新增随移动方向轻缓旋转的非对称椭圆扫描轨道、古铜短弧与三个采样节点。
4. 更新 `data-effect`、组件测试和纯函数参数断言。
5. 完成测试、类型、构建、性能/体积、32 组页面映射、Docker 和实页目视对照。
6. 更新计划、项目状态和需求追踪，并审查 Git diff；不自动提交。

## 验收标准

- 鼠标附近不再出现方形网格或大面积铁丝网形变。
- 基础点阵明显退后，标题、青铜鼎和路线卡保持第一视觉层。
- 数据透镜由细线断续椭圆、少量古铜节点和柔和环形点响应组成，移动方向变化平顺，无霓虹拖尾和持续自转。
- 静止后 RAF 停止，离开后回弹；减少动态、高对比度、强制颜色、pen/touch 和低帧率降级不变。
- 交互代码仍低于 `18,000 B minified / 7,000 B gzip`，全部自动化与生产浏览器验证通过。

## 风险

- 椭圆轨道过于清晰会重新变成 HUD：使用断续短弧、细线和非同心比例，并限制在小范围焦点。
- 方向角可能跨越 ±π 抖动：使用最短角差缓动，不直接替换旋转角。
- Windows 减少透明度模式无法依赖半透明层次：单独使用低对比实色基础点和实色精密轨道。

## 验证结果

- 完成视觉修正：删除全部水平/垂直相邻节点连线，不再形成方格铁丝网；Canvas 效果标记由 `artifact-scan` 更新为 `artifact-lens`。
- 完成层级收口：点阵间距由 `22px` 加疏至 `26px`，青玉/古铜基础点缩至 `.68px / .92px`；最大位移由 `20px` 降至 `12px`，最大缩放由 `2.05` 降至 `1.72`，影响半径由 `170–280px` 收至 `150–240px`。
- 完成高级焦点：鼠标附近使用两层细青玉断续椭圆、三段古铜短弧与三个古铜采样节点；轨道随指针移动方向按最短角差以 `.22` 系数平滑，不持续自转，静止后仍停止 RAF。
- Windows 减少透明度模式改为更浅的实色基础点，焦点轨道继续使用实色青玉/古铜；透明探照层仍关闭。其余 reduced-motion、contrast、forced-colors、pen、touch 和低帧降级未改变。
