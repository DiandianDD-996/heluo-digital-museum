# 桌面预约页场馆信息卡精简

## 1. 目标

修复 `/appointment` 桌面端场馆信息卡被无尺寸约束图标撑高的问题，将其收敛为与预约任务流匹配的紧凑横向信息带。

关联需求：`F-06`、`F-12`、`F-14`、`N-03`、`N-06`。

## 2. 根因

桌面端没有为 `Location`、`Timer`、`Clock` 图标设置宽高。线上 1440×900 实测定位图标被拉伸为 `318.6×318.6px`，两个时间图标分别达到约 `95.5px` 和 `78.3px`，最终把场馆卡撑到 `602.96×532.47px`。

## 3. 影响范围

- `frontend/src/assets/task-pages.css`
- `frontend/src/assets/AppointmentVisitCardLayout.spec.ts`
- `PROJECT_STATUS.md`
- `docs/01-requirements-traceability.md`

不修改场馆信息内容、图片、预约日期/时段、联系人表单、API、鉴权、幂等提交或预约状态机。

## 4. 实施方案

- 在 761px 以上为场馆卡建立稳定 `154px` 横向布局，图片约占三分之一，信息区使用紧凑内边距。
- 三个图标统一为 `16×16px` 且禁止伸缩，地址和两项到访提示使用清晰正文层级。
- 底部两项提示横向排列并允许在较窄桌面自然换行，不使用大图标或重复卡片边界。
- 760px 以下继续沿用已验收的移动场馆信息带规则。

## 5. 验收标准

- 1440×900 场馆卡高度不超过 `160px`，三个图标均为 `16×16px`。
- 中文/英文、浅色/深色无文字裁切、图标拉伸或页面横向溢出。
- 移动端现有 `146px` 信息带不回归。
- 专项/全量测试、类型检查、生产构建、页面映射和 `git diff --check` 通过。

## 6. 风险

- 历史 CSS 多层覆盖，必须以最终计算样式而非单条源码规则验收。
- 本轮不提交真实预约，不把实体设备和系统强制颜色标记为已验证。

## 7. 验证结果

- 本地 1440×900 英文深色与中文浅色实页中，卡片高度均为 `154px`，三个图标均为 `16×16px`，图片使用 `object-fit: cover`；内容无裁切，页面横向溢出为 `0`。
- 本地 390×844 中文浅色移动端继续使用既有布局，卡片约 `147.33px` 高、图标 `14×14px`，无内容裁切或横向溢出。
- 前端全量 Vitest `48` 文件 / `260` 项、类型检查、生产构建、构建预算、`qa:pointer-pages 32/32` 与任务文件 `git diff --check` 通过。
- 本轮未提交真实预约、未发布 PocketBay；本地前端为 HTTP `200`，但后端健康接口当前返回 `503`，因此未重复执行依赖后端的预约提交链路。实体 iOS/Android 与系统强制颜色仍待验收。
