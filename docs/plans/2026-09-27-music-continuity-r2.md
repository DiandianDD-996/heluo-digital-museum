# 配乐连续性第二轮修订

> 日期：2026-09-27。状态：r2 三曲与原稿比较页已交付，等待第二轮听感反馈。关联需求：F-01/F-02/F-05、N-03/N-06。

## 用户反馈与目标

用户试听首轮三份小样后认为连续性不足，尤其青铜鼎近观《观器·温金》。本轮沿用既定的温润、雅俗共赏、按场景适配原则，优先改善完整乐句的方向、弦乐音符间的衔接和不同声部交接。首页与阅读段做较轻的衔接调整，仍保持场景差异。

这里把“连续性”先解释为音乐线条和乐句之间能自然延续；不把它直接等同于需要更大音量、更多混响或持续单音。保留适量句末呼吸，用户仍需试听确认这一解释是否贴近感受。

## 范围与分工

- 保留第一轮 `score.json` 和六份 r1 WAV，作为同响度对照。
- 新建 `scripts/music-audition/score-r2.json` 与修订说明，由谱稿子任务独立负责；新编排仍使用已有许可明确的音源。
- 主代理负责 `render.py` 的版本化输出、必要的声部衔接处理、试听页版本比较与检查脚本。另一子任务只读核对现有采样/包络和实际音频中的能量下陷。
- 结果输出至已忽略的 `artifacts/music-audition-2026-09-27/`，使用不同版本文件名，保留原稿文件。
- 同步本计划、创作方案、项目状态和需求追踪表；不修改前端产品、业务接口或 Docker，不安装新依赖，不提交或推送 Git。

## 实施步骤

1. 核对谱面空档、弦乐起落与声部交接，区分真正静音和持续时间短但音量明显衰减的断续感。
2. 将青铜鼎主线组织为较长的连贯乐句，在声部更替前安排接续；按需调整样本包络，保留清楚的音高与呼吸。
3. 对首页/阅读段做克制的乐句衔接修订，避免用持续低音或更密的强起音填满空间。
4. 导出 r2 的等响度与建议场景音量版，在单播放器中提供 r1/r2 同位置比较。
5. 检查 WAV、输出散列、削波、峰值、响度、衔接前后的能量变化及浏览器播放行为，交付可听的修订稿。

## 验收标准与风险

- 三首曲目身份与场景用途仍能从谱面清楚辨认；青铜鼎有明确连续主线，声部交接有重叠承接而非轮流停顿。
- 原稿完整保留；同曲 r1/r2 实际响度相近，避免靠音量变化制造偏好。
- 六份新 WAV 可解码，56 秒双声道，削波为零，开头和结尾平稳。
- 试听页不自动播放、不叠音，版本切换可保留当前进度；播放与窄屏布局经过实际浏览器检查。
- 用户对连续性、沉闷度与专注影响的反馈单独记录。数值覆盖率或能量均匀不能代替音乐自然度；音符过度重叠可能造成和声含混，需保留适度分句和薄配器。
- 本轮仍为短曲试听，未覆盖长时间循环、真机听感或网站导航衔接，不继承历史生产验收。

## 验证结果

### 原因与修订

只读核对确认两项问题叠加：竖琴在采样自然衰减后，接班大提琴仍未进入；部分中提琴采样起势晚，记谱上已有承接音，实际主体却在音符快结束时才建立。原版青铜鼎在 17.3 秒附近最低为 -51.45 LUFS、37.7 秒附近为 -41.37 LUFS（400ms K 加权窗口），不能把这种测量直接当作主观静音阈值。

- 新谱 `score-r2.json`：三曲共 251 个事件，首页/阅读 86/84 不变，青铜鼎 85→81。青铜鼎三组大提琴句内的平均计谱空档由 0.434 秒缩至 0.060 秒；五处中提琴从支撑改为轻接力，16.56–18.28 秒一处按实际音频低谷提前校正。计谱并发峰值保持 5，含名义释放的峰值保持 6；没有新增持续音床或提高混响。
- `render.py`：只对 28 处标记 `connected` 的弦乐启用 RMS 主体入口定位，保留 80ms 入声前缘，加 120ms 平滑起音和 320ms 释放；验证裁切后源长度覆盖整条音符及释放。这是采样衔接处理，不宣称真实连弓录音。自然发音分支保留。
- `listening.html` / `check-preview.mjs`：试听页默认展示青铜鼎 r2，新增 R1/R2 同位置切换与单播放器竞态处理；生成物与原稿均可下载。
- 新建 `compare-continuity.py`：校验两版输出散列、原稿保留、响度差，记录指定交班窗口与其他低电平窗口；`.gitignore` 只排除本目录生成的 Python 缓存。
- `README.md`、`REVISION-R2.md` 记录复现命令与编排变化；方案、状态、追踪表同步更新。首轮源脚本/谱稿/模板/报告快照保存在 `artifacts/music-audition-2026-09-27/r1-source/`。
