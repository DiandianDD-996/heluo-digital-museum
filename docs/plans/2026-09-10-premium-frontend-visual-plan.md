## 1. 设计结论

让网站像一场经过认真策展的数字展览：远看有展馆空间，近看有器物细节，操作时有清楚的秩序。高级感由主次、比例、图片质量、文字密度和跨页一致性共同建立。

保留已有“日间月白展厅 / 夜间深墨展厅”、青铜鼎、系统宋体、青玉与古铜配色。最值得投入的改动是：首页入口收敛、器物近景与展签、内容区留白、共享表面减负、手机构图独立处理。

本方案是同日 holistic-optimization-plan.md 中前端视觉部分的细化，不替代其部署、内容可信度和后端任务。采用 frontend-design 的主题取材、排版角色、单一视觉记忆点和克制动效原则；不另立与 design.md 冲突的已生效设计系统。以下新增数值均为提案，实施时再同步 design.md。

| 强拟物石材与金属控件 | 材质鲜明 | 按钮和边框容易成为视觉主角；只保留轻微切边与实体操作感 |
| 河洛纸墨 · 器物为心（推荐） | 延续品牌，兼顾文化表达、阅读和操作 | 需要精确处理图片尺度、字重、留白及单层边界，不能仅替换颜色 |

唯一记忆点：“从馆廊远景，走近一件器物。”首页第一屏保留建筑空间；第二屏用器物局部、完整器形和简短展签建立近距离观察。两屏由同一器物或明确关联的内容衔接。若现有鼎图、模型、文物记录并非同一件，不强行叙述为同一原件，先核对关联。

设计自审：减少通用的大口号、三个等权功能卡、没有顺序意义的 01/02/03；真实日期、预约步骤和藏品编号可以保留。艺术表达集中在器物舞台，操作区保持稳定。

## 4. 视觉规范提案

### 色彩与明暗

以下六色为设计沟通色板，不是已计算的线上色值；实施映射到现有语义令牌，先在状态板核验对比度，再决定是否需要调整现有 OKLCH 值。

| 名称 | 提案色值 | 使用角色 |
|---|---|---|
| 月白 | #F5F7F5 | 浅色画布，偏中性，避免整屏泛黄或泛绿 |
| 青灰 | #E5EBE7 | 分区与低层次底面，区分背景和内容 |
| 墨玉 | #203D35 | 浅色标题、重要文字、深色品牌锚点 |
| 深玉 | #315D4C | 浅色主要操作面、明确的选中状态 |
| 古铜 | #A88954 | 展签细节和低面积强调；不直接用于白底小字 |
| 夜墨 | #171C1A | 深色画布与媒体舞台基底 |

正文、次要文字、边界、危险/成功/焦点继续沿用现有语义系统，逐项验证。深色保持画布、分区、内容面、浮层四级可辨；文字以月白及其可读派生色呈现，主要操作使用现有古铜语义并核验文字搭配。真实图片不整体染绿，不把浅色图简单压暗替代夜景。

视觉面积以中性表面和图片为主；古铜装饰建议低于单屏 5%，状态颜色不计作品牌装饰。金色不承担错误、禁用等多种语义。

### 字体、密度与版心

- 展览标题与重点器物名：沿用 STSong / Songti SC / SimSun 系统衬线，正体；不下载新字体。Windows 宋体无连续字重时用尺寸与间距建立层级，不靠伪粗体。
- 正文、任务标题、按钮：沿用 Microsoft YaHei / PingFang SC / Hiragino Sans GB / Arial；价格、日期启用 tabular-nums。
- 首页封面标题提案：桌面 64px、平板 48px、手机 36px；英文单独评估换行。任务页沿用已定 36px / 28px；器物名 28px / 24px；正文 16px，长文 17–18px；辅助文字优先 14px。
- 正文行高 1.7–1.85，标题 1.15–1.3；中文不拉开大字距，英文标签仅小范围使用。不要把 12px 浅灰字当高级感来源。
- 公共页延续最大 1200px 版心；桌面 12 列、24px 槽，手机边距 20px，320px 下可收至 16px。正文阅读区约 680–760px，目录在宽屏占独立侧栏。
- 区域间距建议桌面 80–112px、手机 40–56px；分组内部 24–32px、标签至内容 8–12px。沿用 4px 间距令牌，不把每个区域都塞进同一种大卡片。

### 表面与控件

保留 data-glass 合同及现有性能降级。导航和浮层按合同处理环境感；正文背景、表单、后台列表确保稳定可读。单张内容卡只保留一个清楚边界，图片、说明区和按钮不各自再套发光外框。

卡片与控件延续 8px 圆角，紧凑细节可 6px；边界 1px；阴影只表达浮起关系，优先一个轻阴影。主按钮实体色、次按钮轻描边、文本链接有明确 hover/focus；同一任务区域只设一个最高强调操作。触控目标至少 44×44px，主要表单控件优先 48px。

状态板必须含 default / hover / focus-visible / pressed / disabled / loading / error / success。选中日期、筛选、状态徽章用文本、形状或图标辅助，不只依赖颜色；边框变化不引起布局跳动。

## 5. 页面方案

### 首页：一张封面，一次走近，一条清楚的继续路径

首屏继续使用现有馆廊原图。原图的鼎在画面中央偏右的远处，适合建立纵深；标题避开器物、玻璃展柜和透视终点，不把大号文案压在鼎上。主操作沿用“探索馆藏”，次操作“进入数字展厅”；预约保持导航可达，路线板降为轻量引导，不与主标题争抢注意。

桌面建议结构（布局提案，并非生成效果图）：

```text
品牌                     主要导航                   语言 / 主题 / 账户
┌─────────────────────────────────────────────────────────────┐
│ 小引句                                                      │
│ 河洛数字             馆廊纵深与青铜鼎                        │
│ 博物馆               保留完整器形与视觉通道                  │
│ 简短说明                                                    │
│ [探索馆藏]  进入数字展厅 →                  轻量参观入口     │
└─────────────────────────────────────────────────────────────┘
       器物近景（约 7 列）    器物名、短故事、资料入口（约 5 列）
       三类真实主题入口：青铜 / 玉石 / 河洛故事，图文轻重有别
       精简参观信息与预约入口（资料确认后）
       页尾：品牌简介、内容来源、必要站点信息
```

首页 1440×900 首屏建议导航约 72px、主舞台约 640–700px，适度露出下一段，让访客知道可以继续阅读。实际以图片裁切、英文换行和浏览器可用高度校准，不锁死全屏高度。

第二屏建议用现有重点器物近景，配 80–140 字入门说明和最多三个有来源的观察点；无可靠观察资料时先用已发布摘要。器物区与故事区保持一个共同底面，减少各自包卡。无需为装饰新增轮播、视频或首屏自动 WebGL。

手机单独编排：精简品牌栏→短标题与说明→完整器物/馆廊主体→主要按钮→下一段；利用已有竖版图验证焦点位置。底部五项导航继续保留，主操作不与它重叠；禁止将桌面浮层直接等比缩小。

### 探索与详情：让展签服务于观察

保留当前搜索与分类结构。首屏标题、搜索、筛选形成连续工具区，其下由一件重点器物带动列表；已有主次成立时只调整图文占比。分类切换及搜索结果使用稳定网格，避免每次变化都制造不规则布局。

器物图使用 contain 或明确完整器形的裁切；同类图统一相对占比、基线和底面。环境/文章图片可以 cover，不能把玉璧和青铜鼎机械裁成同一种满幅比例。重点区域建议完整图 4:5，故事横图 16:10，普通图框比例通过实际素材决定。

展签顺序：真实分类/年代（有数据才显示）→器物名→一至两行摘要→详情入口。减少无意义编号和重复“查看更多”。详情保持明确标题、图片、正文、资料来源，再给相关 3D 入口；不编造馆藏编号、出土地点或年代。图、模型、文章关联未核实前不做同物对应承诺。

### 数字展厅：器物像展品，工具像工具

列表封面呈现完整器物，名称与可用互动方式清楚。3D 页保留既有封面→启动→模型、实体/点云、视角和信息抽屉。主角是模型；说明集中一侧或底部，工具条不围满四周。

桌面最多保留一个主工具组与一个信息入口；移动视角按钮保持现有可达逻辑，不为整齐隐藏第五个视角。加载、失败、重试及不支持状态使用同一舞台底面，避免突然跳成通用报错框。空间、灯光或点云参数改变列为独立后续项，本轮优先界面层。

### 预约、商城与账户：清晰的操作也有质感

预约延续日期/时段/联系人三段结构，进度序号在此有真实意义。选中日期用明确的深玉实面，约满与未开放有文字区别；右侧摘要与主表单顶线对齐，移动摘要沿用抽屉。装饰图控制高度，保持日期和下一步首屏可发现。

商城以产品图片、名称、价格为视觉顺序；同排图框与价格/按钮基线一致，桌面布局按购物车侧栏剩余空间决定列数。把商品文案从厚重叠层收敛为单层信息区；购物车保持独立区域。模拟支付说明紧邻结算动作，库存不可因低对比而难读。

登录使用安静底面和聚焦表单；表单标题与正文用无衬线，宋体只留在辅助品牌区。个人中心优先展示近期预约、订单状态和下一步；弱化与任务无关的巨大欢迎区。重置密码、空记录、断网和失效登录延续相同样式。

### 内容与运营后台：同一品牌，更高信息密度

保留现有侧栏和工具栏布局，沿用公共色彩、8px 圆角和状态徽章。后台不增加馆廊大图；主要工作区保持轻实体面、清楚表头与行分隔。桌面记录行建议 48–56px，操作按钮触控区至少 44px；移动记录卡只展示核心字段，详情按需展开。

筛选、列表、编辑区用对齐和空间区分；一次编辑只突出一个保存动作。发布、撤回、库存、预约和订单状态沿用真实业务含义。图表仅用于已有统计，不为视觉填充虚假趋势。

## 6. 素材与动效合同

第一轮复用已授权、已记录来源的馆廊、器物与商品素材，不以全站换图作为前提。先制作资源审查表：用途、现有文件、尺寸、焦点、来源、是否符合真实内容。只有无法通过裁切改善的素材才补制。

器物图片保持原始结构与色彩。概念环境图不包装成真实馆舍照片；新图不包含界面文字、商标或数据，文字由 DOM 承载。桌面/手机分别裁切，首屏使用已有响应式资源；避免把大幅主视觉作为 CSS 背景后失去资源优先级控制。

沿用现有 GSAP/Motion 能力，不新增动画库。封面单次呈现可 400–600ms，总序列控制在约 800ms 内，按钮始终可操作；普通区块沿用 220–360ms、最多 8px 位移。hover 主要改变边界/色彩，器物图可极轻缩放，禁止大幅倾斜商品和长时间悬浮。

保留已确认的细环光标与青玉/古铜点阵，不额外增加拖尾、光斑或全屏粒子。表单输入保持原生光标，点阵不覆盖文字与焦点。减少动态、粗指针、强制颜色等继续按当前实现降级；不在此方案擅自改写设备策略。
