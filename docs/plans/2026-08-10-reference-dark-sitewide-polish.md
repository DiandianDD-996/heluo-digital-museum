# 参考图式全站深色模式精修计划

## 目标

在不改变路由、API、权限、预约、订单、模拟支付、后台状态机和 Three.js 生命周期的前提下，将用户参考图中的“近黑夜间展馆、暖象牙文字、古铜金重点、低透明深墨玻璃”扩展到完整公众前台、账户页、3D 展项和内容/运营后台。首页作为视觉基准，其余页面按业务密度调整，不把运营后台做成展示型海报。

## 关联需求

- F-01 至 F-14：公开浏览、3D、预约、商城、账户、后台管理与深色主题。
- A-01、A-02：图片和 3D 素材可追溯、体积适合 Web。
- N-03：桌面与移动端无关键横向溢出、遮挡或不可读控件。
- N-06：前端测试、类型检查、生产构建和核心流程文档通过。

## 页面范围

- 公众前台：首页、馆藏、内容详情、数字展厅、3D 展项、预约、商城。
- 账户：登录、注册、找回密码、个人中心。
- 后台：内容管理、运营管理及其统计、工具栏、表单、记录和操作状态。

## 影响范围

- `frontend/src/assets/main.css`：建立全站参考图式深色层级，统一导航、画布、媒体、卡片、表单和后台工作区。
- `frontend/src/views/HomeView.vue`：保留首屏主入口和路线语义；修复装饰图片重复朗读。
- `frontend/src/assets/darkThemeCohesion.spec.ts`、`frontend/src/test/HomeView.spec.ts`：锁定全站深色覆盖、移动可见性与首页业务入口。
- `frontend/public/media/editorial/museum-store-dark-image2-v1.webp`：通过用户已登录的网页版 GPT / Image 2 生成的夜间文创展台。
- `frontend/public/media/editorial/README.md`：登记素材来源、用途、尺寸和限制。
- `design.md`、`PROJECT_STATUS.md`、`docs/01-requirements-traceability.md`：同步设计合同、状态和验证结果。

## 实施步骤

1. 使用真实生产路由逐页检查深色主题，记录与参考图在画布、文本、强调色、媒体和玻璃层级上的差距。
2. 以首页近黑展馆为基准，收口共享深色令牌和全站导航；为公开展示页、任务页和运营后台分别控制密度。
3. 深化馆藏、详情、展厅和 3D 页的媒体舞台与信息板；避免浅色图片直接浮在近黑画布上。
4. 将预约、商城、登录、个人中心的表单、摘要、空状态和主要操作统一为低透明深墨玻璃与古铜金重点。
5. 将内容/运营后台统一为近黑紧凑工作台，保持字段、状态和操作优先，不放大装饰元素。
6. 使用网页版 GPT / Image 2 生成无文字夜间商城环境图，压缩为版本化 WebP 并登记来源；无缺口的页面复用现有素材。
7. 补齐 `980px`、`768px`、`760px` 和短屏规则，保证移动路线图、底部导航、44px 控件和中英文标题不重叠。
8. 运行专项与全量测试、类型检查、生产构建、页面映射、Docker、真实 Chrome 双主题和三角色核心路由回归。

## 验收标准

1. 全站深色主题均使用近黑深墨画布、暖象牙文字和少量古铜金重点，不再出现大面积亮绿色、白色加载面板或日间背景拼接。
2. 首页、馆藏、展厅、详情、预约、商城和账户页的导航、卡片、媒体、表单和状态属于同一视觉系统；浅色主题不回归。
3. 后台保持紧凑可扫描，统计、工具栏、表单、记录和操作层级清晰；普通用户无法访问管理员接口的规则不变。
4. 商城深色模式使用无文字夜间文创展台，产品真实可辨，左上保留标题空间；素材有版本化文件和来源说明。
5. 所有可见主要控件高度至少 44px；`320x568`、`390x844`、`768x1024`、`1440x900`、`1672x941` 无关键横向溢出、文字遮挡和导航裁切。
6. 中英文、主题刷新持久化、减少动态、减少透明度、高对比度和强制颜色模式保持可用。
7. 前端全量测试、类型检查、生产构建、页面映射、`git diff --check`、Docker HTTP/API health 和真实 Chrome 控制台检查通过。

## 风险

- `main.css` 有多轮历史视觉规则，本轮使用一个末尾的全站深色作用域层收口，不重排全文件或修改浅色规则。
- 全局把青玉主操作直接改成金色可能破坏成功/状态语义，因此古铜金只用于主题重点，成功、警告、危险仍保留语义色。
- 生成素材只承担环境，不包含文字、UI 或业务状态；若生成结果不满足构图和可读性，不进入生产目录。
- 后台功能密度高，视觉统一不得牺牲字段标签、状态对比和批量操作效率。
