# 洛笙青铜鼎实时问答预览

关联 LS-02、LS-03、LS-04、LS-06、LS-08。目标是在通过视觉评审的展签上，以当前看点和可核对证据回答自然语言追问。

1. 在本机回环预览中增加显式选择的 Chat Completions 传输，凭据仅由 Java 进程读取。
2. 识别明确看点与缺少指代的问句。模型模式在关键词未命中时提供经复查的当前看点证据，或最多三张本展项观察资料。
3. 展签区分模型生成、资料答复和测试模式，保留引用、限流、超时、退出与用户确认动作。
4. 本机替身验证请求格式、上下文和页面。真实供应商经确认后用受控问题验收。默认生产功能开关及卡包签核状态保持原样。

预览只使用单展项公开安全的数字模型观察，不读取账户或内部卡包。外部模型可能产生费用或收到输入的原文，启用前需确认供应商、账号和本地调用范围。

## 本机运行

经确认后，在 PowerShell 环境中设置 `LUOSHENG_MANUAL_PREVIEW=1` 和 `LUOSHENG_MODEL_PREVIEW=1`。设置 `LUOSHENG_MODEL_ENDPOINT` 为供应商完整 HTTPS Chat Completions 地址，`LUOSHENG_MODEL_NAME` 为支持 JSON 输出的模型。通过进程环境提供 `LUOSHENG_MODEL_API_KEY`。在 `backend` 运行 `mvn -B '-Dtest=GuideHttpIntegrationTests#serveManualPreview' test`，从输出打开 `LUOSHENG_MANUAL_URL`。预览只监听回环地址，15 分钟自动退出。每轮等待整条文本完成后显示，单次生成上限 12 秒，同步生成并发 1，整个预览最多 20 次模型调用。

离线联调可在 `frontend` 运行 `node scripts/luosheng-model-stub.mjs 5196`，将端点设为 `http://127.0.0.1:5196/v1/chat/completions`，模型设为 `stub`，凭据占位值设为 `loopback-test`，并加 `LUOSHENG_PREVIEW_SMOKE=1`。同一 Maven 命令自动运行 Chrome 检查并结束。

只看统一向导界面时，无须模型或凭据：在 `backend` 的新 PowerShell 进程设置 `LUOSHENG_MANUAL_PREVIEW=1`、`LUOSHENG_UNIFIED_CHECK=1`、`LUOSHENG_MANUAL_PORT=5197`，不要设置模型和冒烟开关，然后运行上面的 Maven 命令。打开 `LUOSHENG_MANUAL_URL` 中的普通中文首页。使用本机测试回答和 H2 的明日 10:00–11:00 六席演示时段，15 分钟后自动退出，不是场馆实际数据。

使用批准的 HTTPS 端点并设置 `LUOSHENG_PREVIEW_SMOKE=1` 时，Chrome 会通过展签提交固定测试问题，两个主题合计最多 6 次生成。脚本核对鼎耳的俯视建议、三足的遮挡线索和对应图版，以及出示依据、缺证和清除旧依据的流程。日志记录两处生成的答复和显示耗时，供后续复核内容及语气。手动预览时取消该开关。

## 验证记录

Chrome 在 390px 深色和 1440px 浅色完成本地协议联调，覆盖无看点时澄清、鼎耳自由改写、三足指代、回看依据、缺证及旧依据清除。前端 506 项单测、类型检查、构建和资源预算通过。模型供应商的响应质量、用时、额度及真机交互待验。

后端全量 150 项中 148 项通过，含合成对话及预设讲解 Chrome 回归。两个按开关跳过的项目分别独立通过本地模型协议联调及生产浏览器隔离检查。

DeepSeek 官方模型列表接口返回 HTTP 401。检查了本机进程和用户环境中的同名凭据，两者一致。认证阶段即失败，浏览器尚未取得真实模型回复。新增验收分支后，390px 深色和 1440px 浅色均通过本地回环复测。

凭据更新后，官方模型列表接口返回 HTTP 200。选择 `deepseek-flash` 验收青铜鼎展签，390px 深色和 1440px 浅色均从浏览器通过看点复述、指代追问、图版依据和缺证检查。Maven 集成测试 1 项通过。四条带图版依据的模型回复从提交到可读分别约 4.9、3.9、4.4、2.4 秒。本机短时互动预览供进一步体验，正式访客试用、真机和更大规模质量复核尚待开展。
