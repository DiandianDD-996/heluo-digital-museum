## 1. 目标与实施原则

把已有辨识度的数字博物馆，提升为定位清楚、内容可信、操作可靠、能够复现验收结果的完整作品。主要面向 PRODUCT.md 中的年轻文化探索者，同时覆盖管理员维护流程。

**统一用户目标，拆分前端、后端、内容与部署职责，按完整流程验收。** 不采用“全部前端做完再做后端”的串行方式。每个批次交付一个可验证结果；接口和数据契约先定，界面与服务再分别实现。

沿用 Vue 3、Spring Boot、MySQL、Three.js 和既有设计系统。第一版仍是模拟支付，不引入微服务、真实支付、短信、第三方登录或新的付费平台。已有工作树改动全部保留。大规模换图、框架迁移、全站 CSS 重写不属于本方案。

范围覆盖首页、探索与详情、数字展厅、预约、商城、账户、内容后台、运营后台及两种部署方式。已经实现的能力先复验，只有复现缺口才修复，避免重复建设。

## 3. 产品定位与设计简报

### 定位与需要确认的事实

规划暂按“河洛文化数字展示与业务流程演示项目”设计，不假定存在真实运营场馆。此项是工作假设，不能直接发布为事实；实施公开定位文案前确认是否对应实体场馆。

- 若为演示项目：首页及预约入口说明演示性质；预约为流程体验，不承诺真实入馆；商城明确模拟支付、不产生真实交易。
- 若有真实场馆：由项目方提供可核验的机构、地址、开放时间、预约规则和联系方式，再使用真实到访文案。不得编造资料。
- 文物原件信息、项目概念展品、模型重制、环境插画分开标注；来源可展开阅读，不用整屏技术说明阻断浏览。

### 视觉方向

继续使用 design.md 的“河洛纸墨、东方编辑策展”体系。场景：年轻访客在日间手机上快速探索，也可能在夜间电脑上细看器物，因此保留浅深主题，由用户选择。首页保留展馆空间感；表单与后台以清楚、可读、可操作为优先。

参考锚点使用当前首页的展馆与青铜鼎构图、探索页的不对称器物展签、现有预约工作台。无需新一轮方向生图；现有素材足以完成本轮层级优化。

主行为为“理解一件器物并继续探索”，到访或模拟预约为后续行为。界面表达采用克制配色、一处主按钮、稳定排版；动效只作反馈或有意义的探索提示。

### 首页推荐结构

1. 首屏：品牌、简短定位、一项突出主操作“探索馆藏”，次操作“体验 3D”；右侧路线板降低视觉重量，避免重复同等优先级的选择。
2. 一件器物的故事：约 150–250 字入门解释、三个观察点、资料性质与来源入口，链接到真实存在的详情。学术事实经来源核对，概念器物不编造出土信息。
3. 三个主题：青铜、玉石、河洛故事，点击进入对应筛选结果；保留有用的分类，减少无信息增益的英文标签。
4. 参观或演示预约说明：在定位确认后提供准确须知和唯一预约入口。第一轮合并未兑现的经典/亲子/学术路线，不新增路线数据库。
5. 页尾：项目介绍、内容来源说明、适用的隐私与联系信息；不用另一组重复大按钮结束页面。

6. sitemap 使用配置化正式基址和绝对 URL，包含已发布公开内容；排除账户/后台/未发布内容。基址新增配置同步示例和部署文档。内容较少时可构建生成，不先引入 SSR 框架。
7. 检查 iframe 的前进后退、刷新、直接访问、复制分享。优先平台官方路由同步能力；若需 postMessage，严格限制 origin 与路径。平台不支持时记录限制，不绕过跨域边界。

验收：同一发布版本下 10 分钟轻量观察至少 20 轮，首页为 200 且含实际应用入口；health/ready 为预期 JSON 且状态 UP；无未解释 204/5xx。冷启动单独计时记录，不能只做热态循环。sitemap 无登录可访问、XML 可解析、loc 全为正式绝对 URL；普通用户的受保护接口依旧拒绝越权。上述短期采样不等于 SLA。

### 阶段 E：移动、性能与发布验收（P1，长期增强为 P2）

- 视觉基线：390px/1440px 的核心页面 × 中英文 × 浅深主题；320/375/768/1920px 检查关键区域。截图以实际页面为准，不能只测直达 URL。

## 9. 风险控制与恢复

| 风险 | 控制措施 |
|---|---|
| 平台休眠、外层代理或 iframe 不受应用控制 | 先确认请求归属与平台能力；迁移/常驻费用单独决定 |
| 全局 CSS 叠加导致局部修复破坏其他页 | 先定位 computed styles 与所有权；复用令牌，局部变更后跨页验收 |
| 线上数据与迁移初始值不同 | 迁移前只读核对，限定目标与前置条件，保留原关联；不改历史迁移 |
| 内容真实性未知 | 把待确认事实留空或明确标注；不生成虚假馆藏出处和机构信息 |
| URL/权限调整扩大匿名访问面 | 精确资源匹配、正反例测试；保留 API 与 ADMIN 边界 |
| 多批工作覆盖现有未提交文件 | 保存本轮差异证据，逐文件审查；不 reset、覆盖或提交用户工作 |

代码恢复使用本轮独立差异与上一个已验证构建，不重置整个工作树。数据库使用经过测试的补偿操作；线上恢复/部署仍须在授权范围内执行。
