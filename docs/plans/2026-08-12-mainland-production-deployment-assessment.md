# 中国大陆公网部署可行性评估与实施计划

- 日期：2026-08-12
- 关联需求：N-05、N-06
- 状态：评估完成，等待云资源、域名与备案条件确认；尚未实施公网部署
- 目标：以零成本或低成本，让中国大陆用户通过正式域名稳定访问完整的河洛数字博物馆，而不是只部署静态前端。

## 1. 结论

不存在同时满足以下四项的成熟长期零成本方案：

1. 中国大陆多运营商网络稳定直连；
2. Spring Boot 与 MySQL 持续在线且数据持久化；
3. 可绑定正式域名并合规提供服务；
4. 不休眠、可备份恢复、可持续运维。

适合本项目的成熟方案是：**中国大陆轻量云服务器单机部署，前端、后端和 MySQL 继续使用 Docker Compose，域名完成 ICP 备案，主机 Nginx 负责 HTTPS。** 初期不购买云数据库、CDN、对象存储或 Kubernetes。

### 推荐优先级

| 优先级 | 方案 | 适用场景 | 判断 |
|---|---|---|---|
| A | 中国大陆 2 核 4 GB、约 7 Mbps、100 GB 轻量服务器 | 课程展示、作品集、低并发公开访问 | **推荐**。内存和 3D 模型下载带宽更稳，按腾讯云 2026-08-12 常规公开价约 `1020 元/年`；购买前检查活动价和续费价。 |
| B | 阿里云 ECS e 2 核 2 GB、3 Mbps、40 GB | 极低预算、访问量很小、接受模型首载较慢 | **最低长期成本候选**。官方活动页当前标注 `99 元/年` 且续费 `99 元/年`，但仅限购 1 台；下单前确认地域、备案资格和活动规则。 |
| C | 大陆云厂商新客/学生限时套餐 | 短期答辩、先完成备案与上线演练 | 可用，但不能把首年促销当作长期成本；必须核对续费、流量、带宽、地域和退款条件。 |
| D | 境外免费 PaaS、Vercel、GitHub Pages、Cloudflare Pages、香港主机 | 静态预览或临时测试 | **不满足本目标**。静态托管缺少完整后端/MySQL；境外链路无法承诺大陆稳定访问；部分免费服务会休眠或限制持久化。 |

## 2. 仓库与运行时检查结果

### 2.1 实际系统边界

- 前端：Vue 3、TypeScript、Vite，生产环境由 Nginx 托管。
- 后端：Spring Boot 3.5、Java 17、JWT、邮件通知和后台管理。
- 数据：MySQL 8.4，22 个 Flyway 迁移，预约、订单、库存、用户和操作日志需要持久化。
- 资源：图片、字体和 GLB 随前端镜像发布；没有必须单独部署的用户上传目录或对象存储服务。
- 邮件：本地使用 Mailpit；公网环境必须改用真实 SMTP，不能暴露 Mailpit。
- 接口：前端 Nginx 已将 `/api/` 同源代理到 `backend:8080`，适合单域名部署。

### 2.2 2026-08-12 本机实测

| 项目 | 结果 | 部署含义 |
|---|---:|---|
| 前端生产产物 | `26.29 MiB` | 单机静态服务足够，初期无需 COS/CDN。 |
| `frontend/public` | `14.16 MiB` | 正式 Web 资源体量较小。 |
| 最大 GLB | `4.97 MiB`，有两个版本 | 3 Mbps 理想下载下限约 14 秒，7 Mbps 约 6 秒；实际还要加 RTT、协议和并发开销。 |
| 后端 JAR | `60.44 MiB` | 适合容器运行。 |
| MySQL 数据目录 | 约 `213 MiB` | 当前数据量很小，但仍必须做独立备份。 |
| 空闲容器内存 | frontend `16.17 MiB`、backend `155.7 MiB`、mysql `61.14 MiB`、Mailpit `26.96 MiB` | 去掉 Mailpit 后空闲约 233 MiB；2 GB 能跑 Demo，但构建、峰值、系统页缓存和 Docker 需要余量，4 GB 更稳。 |
| 当前服务 | 首页 `200`，`/api/v1/health` 为 `UP` | 本地运行链路可用，不等于公网生产就绪。 |

`assets/` 中约 `246.88 MiB` 的 Blender 源文件和设计资产不应进入线上运行目录；线上只需要前端 Web 产物、后端镜像和数据库数据。

## 3. 推荐生产拓扑

```text
中国大陆用户
  -> 已备案域名 DNS
  -> 大陆轻量云服务器公网 IP
  -> 主机 Nginx :80/:443
       -> 自动跳转 HTTPS
       -> 反向代理 127.0.0.1:8088
  -> production Docker Compose
       -> frontend Nginx（仅绑定 127.0.0.1:8088）
       -> backend Spring Boot（仅容器内网）
       -> MySQL 8.4（仅容器内网 + 持久卷）

外部服务：
  -> SMTP：密码重置、预约和模拟支付通知
  -> 异地备份：加密 MySQL 备份，可后续使用低成本 COS/OSS
  -> 镜像仓库：国内个人版仓库或离线镜像包
```

选择主机 Nginx 而不是让业务容器直接占用 80/443，便于独立处理证书续期、备案拦截页、访问日志和紧急维护页。服务器安全组只开放 `22`（限制来源 IP）、`80` 和 `443`；不得开放 `3306`、`8080`、`8088` 或 Mailpit `8025`。

## 4. 成本边界

以下为 2026-08-12 的公开页面快照，不是报价承诺：

| 项目 | 极省钱档 | 推荐档 | 说明 |
|---|---:|---:|---|
| 服务器 | 约 `99 元/年` | 常规约 `1020 元/年`，优先找符合规格的活动价 | 极省钱档为阿里云活动页的 2C2G/3M/40G；推荐档参考腾讯云 2C4G/7M/100G。 |
| 域名 | 首年可低至约 `10 元` | 按实际后缀与续费价 | 域名需在境内有资质服务商实名，主体信息须与备案主体一致。 |
| SSL | `0 元/年` 可实现 | `0 元/年` 可实现 | 使用免费 DV 证书并建立自动续期/到期监控。 |
| SMTP | `0` 到低额按量 | 以实际发信域名和发送量为准 | 本项目低频事务邮件；上线前必须验证国内主流邮箱送达。 |
| 数据备份 | 初期可仅占服务器磁盘，但不合格 | 建议增加低成本异地对象存储 | 同机备份无法覆盖磁盘或主机故障。 |

首年最低可尝试控制在约 `109 元 + SMTP/备份`，但 3 Mbps 对 4.97 MiB 3D 模型偏慢。更稳妥的预算应按 **2 核 4 GB、5-7 Mbps 及以上** 的实际活动/续费价格计算。

## 5. 当前不能原样上线的项目项

| 缺口 | 当前事实 | 上线要求 |
|---|---|---|
| Compose 环境 | `compose.yaml` 同时包含 Mailpit 和本地默认行为 | 新增独立生产 Compose 覆盖；生产不启动 Mailpit。 |
| 公网暴露 | frontend 当前直接映射 `${MUSEUM_WEB_PORT}:80` | 只绑定 `127.0.0.1:8088`，由主机 Nginx 对外。 |
| HTTPS | 仓库没有生产证书和 80->443 配置 | 配置免费证书、自动续期和到期告警。 |
| 容器自愈 | 四个容器 `restart=no` | 设置 `restart: unless-stopped`，为 frontend/backend 增加健康检查。 |
| 日志 | Docker `json-file` 无大小上限 | 设置日志轮转，例如 `10m x 3`，避免磁盘耗尽。 |
| 资源边界 | 未设置 Java/MySQL/容器资源限制 | 按 2 GB 或 4 GB 主机制定 JVM、MySQL 和容器内存参数。 |
| 数据恢复 | 有本地 PowerShell 备份/隔离恢复脚本 | 增加 Linux 定时备份、加密、保留周期、异地复制和恢复演练。 |
| 邮件 | Compose 默认指向 Mailpit | 配置真实 SMTP、发信域名 DNS、发件人和送达验证。 |
| 发布链路 | CI 只测试，没有制品发布/回滚 | 构建带 Git SHA 的不可变镜像，推国内仓库或打包传输，保留前一版本。 |
| 镜像来源 | Dockerfile 基础镜像来自 Docker Hub | 避免线上临时构建；在 CI/本机先构建成品，减少大陆拉取失败。 |
| 密钥 | 本地 `.env` 模式正确但未定义生产保管流程 | 生产密钥只放服务器权限受限文件或云密钥服务，JWT 至少 32 字节随机值。 |
| 服务器安全 | 尚无防火墙、SSH、系统更新方案 | 密钥登录、禁止密码/root 远程登录、最小端口、自动安全更新和登录防护。 |
| 备案页脚 | 应用没有备案号展示位 | 获得 ICP/公安备案号后在全站页脚展示并链接官方查询。 |
| 发布事实源 | 当前工作区有大量未提交改动，含未跟踪的 V21/V22 迁移 | 上线前形成可复现提交/标签；不得从脏工作区手工复制到服务器。 |

## 6. 实施步骤

### 阶段 A：购买与合规准备

1. 确认备案主体是个人还是单位；域名实名认证必须一致。
2. 在同一大陆云服务商购买满足备案条件的服务器和域名。
3. 优先选择离主要用户近的大陆地域；本项目不依赖特定地域内网服务。
4. 完成 ICP 备案后再正式解析和开放网站；如要求，完成公安联网备案并展示备案号。
5. 申请免费 DV 证书或配置自动签发。

### 阶段 B：生产配置硬化

1. 新增 `deploy/compose.production.yaml`，去掉 Mailpit、公网数据库端口和本地初始化默认值。
2. 增加重启策略、健康检查、日志轮转、资源限制和只读/最小权限配置。
3. 增加主机 Nginx 配置模板，处理 HTTPS、真实客户端 IP、安全响应头和反向代理。
4. 增加生产 `.env.example`，只描述变量，不包含真实密钥。
5. 增加 Linux 备份、校验、保留和恢复脚本；至少保留每日 7 份、每周 4 份，并异地保存。
6. 配置 SMTP，验证 QQ、163 和常用企业邮箱的事务邮件送达。

### 阶段 C：可复现发布

1. 清理本次发布范围并形成 Git 提交和版本标签，确保 V21/V22 等迁移纳入版本控制。
2. 运行前端类型检查/测试/构建、后端测试、Compose 配置检查和空库 Flyway 迁移。
3. 构建带 Git SHA 标签的 frontend/backend 镜像；推送国内镜像仓库个人版，或 `docker save` 后校验 SHA256 并上传服务器。
4. 服务器只拉取/导入成品镜像，使用固定标签启动；禁止直接使用漂移的 `latest` 作为唯一回滚点。
5. 部署前备份数据库，部署后检查 Flyway、容器健康、HTTP、HTTPS 和三角色流程。

### 阶段 D：上线验收与运维

1. 从中国移动、联通、电信网络分别检查首页、API、图片和两个 4.97 MiB GLB。
2. 验收游客浏览/搜索/3D、用户注册登录/预约/下单/模拟支付、管理员后台 CRUD。
3. 检查证书链、HTTP 强制跳转 HTTPS、Cookie/令牌行为、404/5xx 和日志脱敏。
4. 执行一次加密备份并恢复到隔离库，核对 Flyway 和关键表计数。
5. 建立每日健康探测、磁盘/内存/证书/备份失败告警；每月检查流量包和磁盘。
6. 使用前一版本镜像执行一次回滚演练，确认数据库迁移兼容边界。

## 7. 上线验收标准

- 正式备案域名在中国大陆移动、联通、电信网络无需代理即可打开。
- HTTP 自动跳转 HTTPS，证书有效且已设置续期/到期监控。
- frontend、backend、mysql 均健康；服务器重启后自动恢复。
- MySQL、backend、8088、Mailpit 不暴露公网；安全组仅保留必要端口。
- 游客、普通用户、管理员三条核心路径通过，3D 模型可加载且有失败降级。
- 真实 SMTP 的密码重置、预约通知和模拟支付通知至少各验证一次。
- 日志不含密码、JWT、重置令牌、数据库密钥或 SMTP 密钥。
- 每日备份已生成、校验并异地保存；隔离恢复演练成功。
- 能使用固定镜像标签回滚到上一版本，并记录回滚步骤。

## 8. 风险与不选项说明

- 2 GB 主机的主要风险不是当前空闲内存，而是在线构建、Java 峰值、MySQL 缓存和系统更新叠加；选择 2 GB 时必须离线构建并设置内存边界。
- 3 Mbps 对 3D 首载较慢，不能用小 API 压测结果推断 GLB 下载体验；预算允许时优先加带宽/流量包，而不是先加 CPU。
- 单机方案不提供多可用区高可用，但对课程项目和低并发作品集最符合成本；业务增长后再拆云数据库、对象存储和 CDN。
- 免费 TCR 个人版适合当前个人项目和临时发布，但官方不提供生产 SLA；重要制品应同时保留本地/异地归档。
- CDN 需要额外域名、备案、缓存和费用治理；当前 26.29 MiB 产物和低流量阶段先不上，避免过度架构。
