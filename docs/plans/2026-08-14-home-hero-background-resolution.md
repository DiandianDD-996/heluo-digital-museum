# 首页回廊背景清晰度修复计划

- 日期：2026-08-14
- 状态：已完成（首页专项验收完成；全量页面映射在 Explore 既有就绪元素失败处中止）
- 触发：用户在首页 Hero（`.corridor-home__hero`）浏览器批注中指出浅色、深色主题下的整幅回廊背景被放大后出现清晰度不足和像素模糊。

## 1. 目标

让首页回廊环境图在浅色、深色主题的桌面与高 DPR 显示器上保持清晰，不通过降低 Hero 尺寸、压暗图片或移除背景来掩盖问题；保留既有构图、文字、路线入口、主题切换、路由和业务行为。

## 2. 关联需求与边界

- 关联需求：`F-01`、`F-14`、`N-03`、`N-06`。
- 仅调整首页环境媒体、其素材台账、样式契约、测试与项目文档。
- 不改 Vue 路由、API、鉴权、预约/订单状态机、Three.js 逻辑、标题/路线文案或已有卡片功能。
- 保留现有浅色回廊与深色夜间回廊的独立主题构图；深色模式不能退化为压暗浅色图片。

## 3. 已确认根因

| 主题 | 当前生产媒体 | 像素尺寸 | 问题 |
| --- | --- | ---: | --- |
| 浅色 | `museum-corridor-hero.webp` | `1586×992` | 仅接近单倍桌面宽度，WebP 压缩后在高 DPR Hero 中不足。 |
| 深色 | `museum-corridor-dark-image2.webp` | `1672×941` | 接近单倍桌面宽度，且桌面 CSS 额外使用 `background-size: 130% auto`，造成插值放大。 |

## 4. 实施范围与步骤

1. 以项目已登记的浅色回廊源图和深色夜间回廊为基线：浅色保留细节增强版本，深色沿用原始夜间构图并只做无锐化的 2× WebP 导出；保留源文件与用途记录，不覆盖无关素材。
2. 更新首页 Hero 的背景加载规则：深色模式保留独立夜间图片，取消 `130%` 的人为放大；宽桌面按背景高度缩放（`auto 100%`）以保留完整中心展柜、地面反射和两侧环境，移动端继续使用适合窄屏的高度填充。
3. 增加媒体尺寸/样式契约，防止后续把首页背景换回单倍低清资源或重新引入深色 `130%` 放大。
4. 运行专项测试、类型检查、生产构建、页面映射和真实 Docker 页面回归；分别检查浅色与深色下的加载资源、计算样式、背景清晰度、无横向溢出与控制台错误。

## 5. 验收标准

1. 浅色回廊与深色夜间回廊的 `@2x` 生产文件宽、高均达到对应 1x 文件的 2 倍（并达到高 DPR Hero 的覆盖尺寸），且仍为无文字、无 Logo 的环境媒体。
2. `html[data-theme="dark"] .corridor-home__hero` 不再使用 `background-size: 130% auto`；宽桌面使用 `auto 100%` 保留完整夜间构图，移动端不拉伸且保持窄屏可读性。
3. 桌面（`1433×898` 或 `1440px`）与手机（`390×844`）真实页面中，Hero 背景没有明显像素化、重复图样、拉伸变形或错误裁切；标题、路线卡和开始探索入口可读可用。
4. 浅深主题切换后仍引用各自的独立环境图，且页面无横向溢出、无新增控制台错误。
5. 相关 Vitest、`pnpm typecheck`、`pnpm build`、页面映射、`git diff --check` 与 Docker HTTP 检查通过。

## 6. 风险与回退

- 高分辨率媒体会提高首屏传输量：使用 WebP、高质量但受控的编码，避免加入运行时图片处理库；同时记录最终字节数。
- 当前工作树已有大量未提交修改：只写入本计划明示的首页媒体、`main.css`、相关测试与文档，不重置、覆盖、暂存或提交无关文件。
- 若媒体增强改变了文物、回廊比例或生成出文字/水印，则废弃该输出，保留原生产文件并重新生成；视觉验收以 Docker 实页为准。

## 7. 验证记录

- 媒体：新增浅色 `1586×992` / `3172×1984` 与深色 `1672×941` / `3344×1882` 的 1x/2x WebP，并保留无文字 PNG 源；四个生产 URL 在 Docker 前端均返回 `200`，`Content-Type` 为 `image/webp`，缓存头为 `public, max-age=604800`。
- 样式：`main.css` 已为两个主题接入 CSS `image-set()`；浅色继续使用 `cover`，深色宽桌面改为 `background-size: auto 100%`，不再使用 `background-size: 130% auto`，以避免裁掉中心和周边环境。
- 代码验证：`pnpm exec vitest run src/assets/homeHeroMedia.spec.ts` 通过（`1` 文件 / `3` 项）；包含主题契约的专项组合命令 `pnpm exec vitest run src/assets/homeHeroMedia.spec.ts src/assets/darkThemeCohesion.spec.ts` 通过（`2` 文件 / `20` 项）；全量 `pnpm test` 通过（`35` 文件 / `167` 项）；`pnpm typecheck` 与 `pnpm build` 通过。
- Docker/页面：按项目 Compose 命令重建前端，首页与四个新媒体 URL 均为 `HTTP 200`。真实首页页面映射中，浅色主题 `320×800`、`375×812`、`390×844`、`414×896`、`768×1024`、`1024×768`、`1440×900`、`1672×941` 共 `8` 个视口通过；目视复核 `1440×900` 与 `390×844`，背景清晰、标题/路线入口可用且无横向溢出。
- 深色实页：通过 Chrome CDP 在 `1433×898 / DPR 2` 与 `390×844 / DPR 3` 验收；两档实际加载 `museum-corridor-dark-image2-hd-v2@2x.webp`，计算样式为 `background-size: auto 100%`，横向溢出为 `0`。宽桌面完整保留中心展柜、底部反射和两侧树影，截图未见过度锐化或拉伸；移动端仍以高度填充窄屏。
- 页面映射全套未宣称通过：同一命令在首页 `8` 个视口完成后，于 Explore `320×800` 等待既有 `.collection-head` 就绪元素超时而停止；该失败不影响首页专项结果，也未修改 Explore。
- 性能风险：高密度资源仍采用 WebP 与 DPR 分档，单个 2x 文件约 `0.10–0.55 MB`；真实慢网、实体手机、触控笔和 Windows 系统级强制颜色仍需发布前现场补验。

## 8. 用户反馈修订（2026-08-14）

- 用户反馈深色背景不应继续过度锐化，且 `cover`/大比例显示会裁掉中心展柜底部、地面反射与周边环境细节。
- 已将深色 `hd-v2` 媒体改为基于已确认原始夜间回廊的自然 1x/2x 导出，不再使用 ImageGen 细节增强；宽桌面改为 `background-size: auto 100%`，让完整画面以高度为基准居中显示，深色画布承接两侧留白，移动端仍保持窄屏填充。
- Docker 重建后已重新验证深色 `1433×898 / DPR 2`、`390×844 / DPR 3` 实页：中心展柜、底部反射和左右树影均保留，截图使用自然细节版本，无过度锐化；两档均无横向溢出。
