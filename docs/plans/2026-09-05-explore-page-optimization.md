# Explore 馆藏探索页优化实施计划

## 目标

把 `/explore` 从“视觉首屏 + 下方内容”优化为更明确的馆藏探索工具：首屏更快进入搜索，筛选在滚动中保持可见，重点馆藏与目录更紧凑，保留既有 API、路由、搜索、筛选、分页、主题路径和阅读内容。

## 需求关联

- F-01/F-02/F-03：公开馆藏浏览、搜索、分类筛选与详情跳转
- F-12/F-14：响应式布局、浅深主题与可访问性
- N-03/N-06：性能降级、键盘/高对比度支持

## 实施范围

- 新增 Explore 专用收口样式，避免继续扩大历史全局 CSS 选择器。
- 缩短发现区垂直占用，提升首屏搜索可达性。
- 筛选条改为滚动吸附工具栏，保持当前分类可见。
- 重点馆藏降低装饰边框叠加，强化图片、标题、摘要、操作层级。
- 目录卡改善桌面信息密度与移动端纵向阅读。
- 不改变 API、数据模型、路由、鉴权、业务状态和已有主题路径 SVG。

## 验收标准

1. `/explore` 中文浅色首屏在 1440×900 与 390×844 均可看到搜索入口。
2. 向下滚动后筛选工具栏仍可访问，键盘焦点和 `aria-pressed` 保持。
3. 搜索、分类、分页、详情链接行为不回归。
4. 无横向溢出；浅色/深色、中英文保持可读。
5. `pnpm typecheck`、相关 Vitest、生产构建与 `git diff --check` 通过。

## 风险

- sticky 工具栏可能覆盖站点 Header，需按实际 Header 高度设置 `top`。
- 既有 `route-explore-legacy.css` 与主题覆盖层可能产生优先级冲突，因此新增文件必须最后加载并使用 Explore 页面作用域。
- 不在本轮重写数据加载和组件 API，避免影响线上已验证的搜索/筛选门禁。
