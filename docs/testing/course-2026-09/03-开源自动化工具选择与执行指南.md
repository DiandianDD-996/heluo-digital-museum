# 河洛数字博物馆开源自动化测试工具执行指南

这套工具可以减少手工点击，但不能把“模拟手机尺寸”写成“实机测试”。要获得本轮需要的实机数据，至少一位成员必须在真实 Android 或 iPhone 浏览器上运行；云设备服务、模拟器和 Playwright 的 device profile 只能作为补充。

## 1 推荐工具

| 项目 | GitHub | 当前公开 Star 约数 | 适合本项目 | 能否直接取得真实手机数据 |
|---|---|---:|---|---|
| Playwright | [microsoft/playwright](https://github.com/microsoft/playwright) | 95,957 | 页面导航、响应式、截图、网络请求、登录/预约/商城 E2E；项目已安装 `@playwright/test` | 常规设备配置是模拟；Android 真机有实验性支持，也可连接 Chrome CDP，不能当作 iPhone Safari 真机 |
| Appium | [appium/appium](https://github.com/appium/appium) | 21,949 | 真实 Android/iOS 浏览器的点击、滑动、输入、截图和录屏；可用 WebdriverIO 或 JavaScript 客户端 | 可以；需 USB 调试/设备信任、驱动和本机浏览器 |
| WebdriverIO | [webdriverio/webdriverio](https://github.com/webdriverio/webdriverio) | 9k+ | 用 JavaScript 连接 Appium，组织移动端和桌面端用例、生成 JUnit/Allure 等报告 | 可以，前提是底层连接 Appium 真机 |
| Lighthouse | [GoogleChrome/lighthouse](https://github.com/GoogleChrome/lighthouse) | 30k+ | 页面性能、可访问性、最佳实践、SEO；项目已有 `qa:lighthouse` | 不等同真机；默认是实验室模拟，适合补充性能基线 |
| sitespeed.io | [sitespeedio/sitespeed.io](https://github.com/sitespeedio/sitespeed.io) | 5k+ | 用真实浏览器批量采集 WebPageTest 风格速度、截图和指标 | 可在连接真机/远程浏览器时使用，但配置成本比本轮需要高 |
| k6 | [grafana/k6](https://github.com/grafana/k6) | 31k+ | API/公开读接口并发和 P95；项目已有 `qa:load` | 不能测手机渲染；只由组长在隔离环境运行，不让成员压测线上写接口 |

Star 数会变化，以上是 2026-09-11 通过 GitHub API 查询的数值或约数。另有 [Allure Report](https://github.com/allure-framework/allure2)，本次查询 5,532 星，可汇总 WebdriverIO/Appium 结果、步骤和截图；它是报告工具，不负责执行测试。提交报告时写工具版本和查询日期。Star 高不代表适合所有任务。

## 2 本项目的组合方案

成员 A—D 各自保留一份 Playwright PC/模拟视口报告，再由 A、B 或组长用 Appium + WebdriverIO 在一台 Android 真机跑同样的主流程；若有 iPhone，使用 Appium XCUITest 补一轮 Safari。组长运行 Lighthouse 与 k6，并把结果放入总报告。

项目已有 Playwright E2E、Android Chrome CDP 审计脚本、Lighthouse 和 k6：

- `frontend/e2e/` 和 `frontend/playwright.config.ts`：业务 E2E，当前配置只允许隔离 loopback 环境，不能直接改成线上写入。
- `frontend/scripts/android-device-audit.mjs`：已有 Android Chrome CDP 路由、截图、3D 等实机审计入口；它比临时重写 Appium 用例更适合先交付本项目数据。
- `docs/testing-open-source.md`：本地 MySQL、Lighthouse、k6 的启动、输出目录和指标边界。

建议执行顺序：

1. 组长冻结版本并确认线上只读入口；业务写入使用隔离 Docker/MySQL 和专用测试账号。
2. 每位成员在自己的 PC 跑负责模块的 Playwright 用例或录制用例，保存 HTML/JSON、截图、trace（如包含账号则先删掉）。
3. 真机成员使用 Appium/WebdriverIO，或直接执行 `android-device-audit.mjs`；保存设备型号、系统、浏览器、连接方式、时间、截图/录屏和原始 JSON。
4. 组长用 Lighthouse 手机/桌面各跑目标页面，用 k6 只跑隔离环境公开读接口；把“实验室/接口”与“真机用户感知”分开统计。
5. 成员按 `02-个人首轮测试反馈模板.docx` 填结果；自动化原始输出作为附件，不把工具通过率直接等同需求通过。

## 3 Android 真机优先路径

Android Chrome：启用开发者选项和 USB 调试，在手机授权电脑；电脑确认 `adb devices` 为 `device`，不是 `unauthorized`；手机 Chrome 打开冻结测试地址；通过 Chrome 远程调试端口连接。项目现成脚本需要 `HELUO_ANDROID_CDP_URL`、`HELUO_BASE_URL` 和 `HELUO_ANDROID_OUTPUT`，脚本会为首页、3D、预约、商城截图并记录页面状态。

若使用 Appium：统一固定兼容的 Appium 3、UiAutomator2 driver 和 WebdriverIO 版本；Appium Inspector 为编写用例时的可选工具，组员运行不必安装。能力至少包含平台 Android、真实设备 UDID、Chrome 浏览器、自动化引擎 UiAutomator2。Android 需要 SDK/ADB、兼容 Chrome 的驱动及相应 Java 环境。脚本必须把 `deviceName`、`platformVersion`、Chrome 版本写入报告；截图、录屏和 JSON/JUnit 需要配置采集/Reporter，不会安装后自动全部生成。账号凭据通过本地环境配置传入。

iPhone Safari：启用“设置 → Safari → 高级 → Web 检查器”，使用受信任的 Mac、XCUITest/WebDriverAgent；若小组无 Mac，不要声称 iOS 真机已测，记录“未覆盖”。

## 4 自动化报告最小要求

每份报告必须能回答：哪一个版本、哪一台真实设备、哪一个浏览器、哪个网络、哪个页面、做了什么、预期是什么、结果是什么、原始证据在哪里。至少保留：

- 测试运行时间、工具版本、Git commit 或部署标识；
- 设备型号、系统、屏幕方向、浏览器版本、Wi-Fi/移动数据；
- 用例编号与通过/失败/阻塞/未测；
- 截图或录屏、自动化日志、失败堆栈；
- 页面可用、搜索、表单、3D 模型可操作的耗时；
- 失败是否能复现、首次/重复访问、是否可能受平台休眠影响。

## 5 工具边界和不能造假的数据

Playwright `isMobile`、viewport 设置和 Chrome Device Mode 是浏览器窗口模拟，不是手机 CPU、GPU、触控、键盘、安全区或移动网络。Lighthouse 的 throttling 是实验室网络/CPU模拟，不是真机用户指标。k6 是接口并发工具，不代表页面渲染。自动化用例全绿也不能证明颜色、内容真实性或“没有内存泄漏”；这些结论需要截图、人工复核或专项工具。

不要为了得到全绿而关闭 TLS 校验、跳过证书、硬编码管理员密码、重复点击支付、向线上写入大量预约/订单、提交包含 Cookie/Authorization 的 HAR。线上只做公开浏览和专用普通账号允许的少量流程；无法隔离的后台、并发、过期订单和失败支付标阻塞，交组长在本地环境补测。

## 8 落地前必须完成的适配

开源框架不是输入网址就能判断所有业务是否正确的成品。脚本需要定义“注册成功”“预约编号保存”“模型旋转后视角确实变化”“支付只执行一次”等断言。无明确断言的流程只能报告执行记录，不能自动标成功。

现有 Android 脚本默认输出目录仍包含旧设备/日期，且只列首页、3D、预约、商城四条路由；未覆盖完整馆藏、认证或订单业务。运行前须适配当前选择器、路由、PocketBay iframe 和真实设备元数据，并核对写入范围；不能只改 BASE_URL 就直接让全组运行。现有 Playwright 配置只有 list/JSON 报告，trace 为 off，尚未配置 HTML；上述交付结构是目标，仍需统一补齐采集与打包逻辑。

本次交付是工具调研和执行方案，没有安装 Appium、改动测试代码、连接真机或产生真实测试报告。旧手工任务书保留为用例需求参考，不能当成新自动化包已经可运行。

官方依据：[Playwright Android API](https://playwright.dev/docs/api/class-android)、[Appium 文档](https://appium.io/docs/en/latest/)、[XCUITest 安装要求](https://appium.github.io/appium-xcuitest-driver/latest/installation/requirements/)、[WebdriverIO Reporter](https://webdriver.io/docs/allure-reporter/)。iOS 驱动 10 及以上要求 Appium 3；实际安装统一选正式发布且兼容的版本。
