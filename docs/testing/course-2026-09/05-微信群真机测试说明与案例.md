# 河洛数字博物馆安卓真机自动化测试

## 可直接复制到微信群的通知

各位，我们这轮先用统一自动化脚本收集真实安卓设备上的测试数据，不需要大家逐页手动点击或填写长篇Word。

测试方式：Windows电脑通过USB连接安卓手机，手机Chrome打开 https://heluo.pocketbay.app/，电脑运行脚本。脚本会在手机上自动进入首页、馆藏、展厅、预约、文创和一个3D展项，检查基础显示并生成报告与截图。

大家主要做三件事：连接并授权手机→运行脚本→把报告文件夹压缩发群里。运行时手机保持解锁、Chrome在前台，不要手动切换页面。请用不同型号的真实安卓手机或安卓平板；iPhone、模拟器和电脑模拟手机尺寸不算这次安卓真机覆盖。

我已用一台vivo手机跑过一轮：约75秒，五个普通页面基础检查通过，3D加载超时。这个失败也是有效测试数据，不需要为了全绿反复运行。首次配置电脑不包含在75秒内。

提交：一个ZIP＋一行“姓名、手机型号、网络、测试时间、是否顺利运行”。默认每台设备跑一次；失败时保持环境不变补跑一次，两份结果都保留。不能运行就发错误截图，不用自己改代码。

建议截止：2026年9月18日周五20:00。报告案例和操作步骤在附件。注意：这轮只测公开页面基础可用性，还没有测注册、预约提交、支付和完整3D操作。

## 1 本次实际采用的完整方案

电脑Node.js运行项目JavaScript脚本 → ADB（安卓调试桥）通过USB连接真实手机 → CDP（Chrome调试协议）转发到电脑本地19222端口 → Playwright连接手机Chrome → 进入PocketBay外层中的实际应用iframe → 点击可见页面链接 → 自动判定并保存HTML、JSON和截图。

网页实际在手机的Chrome中渲染，使用手机设备资源。这次没有使用Appium、WebdriverIO、Allure、Lighthouse或k6；也没有启动电脑上的手机模拟浏览器。Playwright是本次脚本使用的开源自动化框架，ADB是Android官方调试工具。组员运行不需要Codex或AI账号。

| 自动检查 | 具体判定 | 范围限制 |
|---|---|---|
| 页面导航 | 点击当前手机上可见的链接，等待目标路径和main区域 | 不代表页面每个按钮和全部数据均正确 |
| 正文显示 | main区域存在且有文字 | 加载提示也可能有文字，仍需看截图确认 |
| 横向溢出 | 实际页面与托管外层宽度溢出均不超过1px | 不覆盖所有弹窗、横屏、键盘或页底状态 |
| 图片 | 采集时已完成加载且naturalWidth为0的图片 | 尚未触发的懒加载图片不在本轮结论内 |
| 页面错误 | 收集当前检查期间的pageerror | 不是所有HTTP失败、控制台警告或后端错误 |
| 3D状态 | 等待running，采集时再次确认running | 不能证明旋转缩放、实际帧率和长期稳定性 |
| 耗时 | 点击到目标路径和main可见；3D另等待running | 单次观察，不是首屏性能、LCP或服务端响应时间 |
| 证据 | 自动保存设备信息、状态、视口截图和JSON | 当前超时分支可能没有截图，失败文字仍会保存 |

这是第一轮“真机基础冒烟测试”：快速确认主要入口是否存在明显异常。前后端完整业务测试另排，不把本轮名称写成“全站所有功能验收”。

## 4 第一次准备电脑

分享包提供最小执行目录 `runner`，不包含整个前后端项目、数据库、管理员账号或node_modules；普通页面只读测试不需要Java、MySQL或Docker。

1. Windows电脑安装Node.js 24 LTS，重新打开PowerShell，执行 `node --version` 和 `npm --version`。下载：https://nodejs.org/ 。
2. 下载Google官方Android SDK Platform-Tools，解压到固定目录；下载：https://developer.android.com/tools/releases/platform-tools 。把包含adb.exe的目录加入PATH，或仅在当前PowerShell执行 `$env:Path = 'C:\你的目录\platform-tools;' + $env:Path`，替换成自己的真实路径。
3. 将群文件ZIP解压到普通可写目录，不在压缩包内运行。在runner目录打开PowerShell，执行 `npm install`。其中Playwright测试依赖固定为本次已用的1.63.0；依赖安装失败请发日志给组长，不擅自换版本。

本次连接的是手机已安装的Chrome，不需要执行 `playwright install` 下载桌面浏览器。首次安装涉及网络下载，耗时与正式测试不同；本分享包尚未在全新组员电脑上验收。

## 5 每次测试只做三步

### 第一步 连接手机

只连接一台设备。手机开启开发者选项和USB调试，使用支持数据传输的线连接电脑，解锁并允许调试。执行 `adb devices`，目标状态应为 `device`。`unauthorized`表示尚未在手机授权；没有设备则检查线缆、USB连接及驱动。

### 第二步 打开网站并运行

在手机应用列表启动Chrome，不要点击微信链接后停留在微信或夸克浏览器。Chrome地址栏输入 https://heluo.pocketbay.app/，等博物馆真实页面出现，返回首页，关闭多余的该站点Chrome标签页。

在runner目录执行：

```powershell
npm start
```

测试时保持手机解锁、Chrome在前台，不触摸、不切应用、不调整网络；不要同时运行其他控制手机的脚本。正常情况下运行数十秒到约两分钟，依设备和网站状态变化；75秒只是本次案例。

### 第三步 查看并提交

终端末尾 `REPORT:` 显示报告路径。输出在分享包根目录 `artifacts/real-device/quick-时间戳/`。用电脑浏览器打开 `report.html`，查看结果和截图；`results.json`是原始数据，通常不用手工阅读或修改。

把该次quick文件夹整个压缩，命名 `姓名_设备型号_20260918.zip`，提交到群里。保留report.html、results.json与所有PNG的相对位置，否则HTML中的图片会丢失。不要提交runner/node_modules、整份项目或凭据文件。

## 7 常见问题

| 现象 | 处理 |
|---|---|
| 找不到adb/node/npm | 安装完成后重开终端，核对PATH与命令版本 |
| PowerShell拦截npm.ps1 | 使用 `npm.cmd install` 和 `npm.cmd start`，不用关闭系统执行策略 |
| 找不到Chrome调试连接 | 先确认 `adb devices`，再确认手机真正打开Chrome、非夸克/微信浏览器 |
| 找不到实际应用iframe | 等平台唤醒进入真实首页；仍失败就提交阻塞信息 |
| 3D等待超时或连接中断 | 保留日志；可在保持页面不变时手动截图，注明是补充截图；不写原因已确定 |
| 退出码1 | 表示存在失败/需复核或连接阻塞；先查看REPORT，不等同没有生成报告 |
| 报告没有失败页面截图 | 当前脚本在超时前可能来不及截图；保留JSON错误并按需补手机截图 |
| 运行结束后adb本地映射仍在 | 当前脚本保留19222转发；不再测试可执行 `adb forward --remove tcp:19222`，然后关闭USB调试 |

## 8 组长汇总口径

按“设备＋Chrome版本＋测试时间＋脚本版本”整理，不把不同版本混成同一次测试。通过、需复核、失败/阻塞分开；3D连接中断属于待定位问题，可能需结合页面、资源、浏览器与WebGL证据进一步判断。

本轮没有覆盖：真实注册登录、预约提交、支付、后端权限、输入边界、双主题全状态、横竖屏全状态、iOS、完整3D旋转缩放、长期发热或内存、网络带宽与标准性能指标。若后续扩大范围，由组长统一更新脚本，再让大家重跑；成员不各自改断言凑通过。

正式提交对象是成员自己设备生成的报告，包内final-report只是案例，不能修改案例姓名后冒充自己的测试。
