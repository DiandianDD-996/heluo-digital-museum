## 首尾循环算法

对原母带 `A` 选取截止时间 `E`，固定重叠长度 `C = 1.8 秒`，网页文件周期 `P = E - C`。把原母带的 `[P, E)` 尾音与 `[0, C)` 开头折叠到输出文件前 C 秒，其余正文保留原 PCM：

```text
N = round(C × 44100)
w[i] = (1 - cos(π × i / (N - 1))) / 2
output[i] = A[P + i] × (1 - w[i]) + A[i] × w[i]     0 ≤ i < N
output[N:P] = A[N:P]
```

| 场景 | 原时长 | 截止 E | 折入开头的尾段 | 网页周期 P |
|---|---:|---:|---|---:|
| 入馆 | 106 秒 | 100 秒 | 98.2–100 秒 | 98.2 秒 |
| 静读 | 110 秒 | 104.1 秒 | 102.3–104.1 秒 | 102.3 秒 |
| 温金 | 115 秒 | 109.4 秒 | 107.6–109.4 秒 | 107.6 秒 |

截止点去掉了母带尾部约六秒的极轻余响及静默。保留下来的末句尾音，在每轮新开头的前 1.8 秒自然退去；开头旋律随相补的 raised-cosine 曲线进入。三首头尾同处 G 中心和声，未增加新音符或改写旋律。

**首次播放的前 1.8 秒也会包含上一轮尾音，因此与独立试听母带开头不完全相同。** 播放器首次开启或切换场景时应短暂淡入。1.8 秒后的正文至周期末，在编码前与原母带对应区间逐样本相同。

PCM 循环最后一帧来自原母带 `A[P-1]`，循环第一帧等于 `A[P]`，二者本来就是相邻帧；前缀末帧也与后续正文保持原有相邻关系。此结构允许资源从 0 秒原生循环，不需要特殊 loopStart、跳过开头或 JavaScript 定时定位。MP3 的编码延迟与末端填充由文件的 gapless 信息描述。

## 编码环境与音量策略

本机和运行容器未找到 ffmpeg 命令行程序；系统 Python 已有 PyAV 18.0.0，附带 FFmpeg `libavcodec 62.28.102` 与可用的 `libmp3lame` 编码器。此次使用现有环境，没有安装新依赖、调用云服务或下载音源。

首轮编码发现这份 libmp3lame 对输入施加固定 0.95 倍幅度，解码后比循环 PCM 低约 0.44555 dB。导出器只补偿这个固定衰减：编码输入乘 `1 / 0.95 = 1.0526315789`，约 +0.445528 dB。三首均使用同一补偿，解码后与循环 PCM 的响度差四舍五入到 0.001 LU 为零。没有逐曲响度归一化、压限或均衡调整。

## 复现与边界

在仓库根目录运行：

```powershell
python -B -X utf8 scripts/music-audition/export-web-r3.py
```

脚本只写上述生产资源目录内的三个 MP3、manifest 和许可复制件，不清空目录，不重新编曲，不触碰其他工作。它要求既有已认可 WAV 与来源记录完整；缺失或散列不符时直接失败，不会联网补齐或默默使用另一版母带。

导出脚本依赖 Python/PyAV/NumPy/SciPy 仅用于离线制作；网站构建和运行使用已导出的 MP3，不依赖这些制作工具。构建资源门禁由前端工作流读取 manifest 并核对文件大小、散列与预算。

文件级的精确循环及 gapless 元数据检查，不能代替浏览器原生循环调度、手机/耳机实机、持续阅读和主观循环听感验收。前端播放接入、真实导航和 Docker 部署由主任务完成；本记录不把这些后续工作提前标为通过。
